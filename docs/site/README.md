# The documentation site

The Astro Starlight site published at
<https://wakamenod.github.io/emacs-claude-code/>.

`.github/workflows/docs.yml` builds it on every pull request and deploys it from
`main`. The workflow has a paths filter on `docs/site/**`: **if a page ever
becomes generated from the Elisp sources, that filter has to gain `*.el` or the
site will quietly go stale.**

Run it with the `docs-*` targets in the Makefile, not with `npm` directly —
`make docs-install`, `make docs-dev`, `make docs-build`, `make docs-preview`.

## What is here

English is served at the root and Japanese under `/ja/`, which follows the rule
`CLAUDE.md` states for the two READMEs: **`README.md` and the English pages are
the source of record, and the Japanese ones follow.** The code blocks, the
command and `defcustom` names and the factual cells of a table are identical in
both; only prose, headings and code comments are translated.

At the time of writing the site is a placeholder: a home page and
`reference/configuration` and `reference/key-bindings`, in both languages, each
carrying a visible note that it is partial. The two deep links in both READMEs
point at those two reference pages, so **they cannot be renamed without changing
the READMEs in the same commit.**

Write pages from the Elisp sources and the tests. The Japanese `docs/*.md` beside
this directory are gitignored working documents: they are not published, and
nothing from them should be copied into a page.

## Four things that will cost you an hour

1. **`base` is not added to hero action links.** Starlight prepends `/emacs-claude-code`
   to sidebar entries, `slug:` and `link:` — but a `hero.actions[].link` in
   frontmatter is emitted verbatim. Write `/emacs-claude-code/reference/...`
   there, spelled out. Getting this wrong deploys a page that returns 200 with
   every link 404, which does not show up in `dev`.

   After a build, this is the check worth running:

   ```sh
   grep -rhoE '(href|src)="/[^"]*"' docs/site/dist --include='*.html' \
     | sort -u | grep -v '^\(href\|src\)="/emacs-claude-code'
   ```

   It must print nothing.

2. **A sidebar group needs `items: [{ autogenerate: ... }]`.** Putting
   `autogenerate` directly on the group was removed in Starlight 0.39 and now
   fails the build outright.

3. **Two build warnings are expected, and every attempt to fix them makes things
   worse.** `The collection "i18n" does not exist or is empty` appears because
   locales are configured; declaring the collection turns one warning into two.
   `Entry docs → 404 was not found` appears because Starlight generates its own
   404; adding `404.md` produces a route conflict instead.

4. **Search only exists after a build.** Pagefind is generated by `astro build`
   and served by `preview`. Searching in `make docs-dev` and finding nothing is
   correct behaviour, not a broken index.

## Adding a picture

`scripts/screenshot.sh` makes `docs/images/session.gif` and its still. It opens a
throwaway GUI Emacs, replays a recorded fixture through the real dispatch and the
real renderer a step at a time, captures a frame after each step, and assembles
them with `ffmpeg`. No CLI and no network, so a picture costs nothing and comes
out the same every time — regenerating should reproduce the committed file byte
for byte.

macOS only. It needs `ffmpeg`, and the terminal running it needs Screen Recording
permission (System Settings → Privacy & Security → Screen Recording), or
`screencapture` answers `could not create image from display`.

To add a scene, put a `shot-step-*` function in `scripts/screenshot.el` and call
it from the driver in `scripts/screenshot.sh` with a `snap` after it. `snap N`
holds a moment by capturing the same frame N times.

The demo project is `/tmp/greet`, a real directory with a real file. The file
really is rewritten when the Edit is allowed, so the source buffer on the left
really does revert — which is the point of the animation, and why the paths in
the transcript and in the left-hand buffer agree.

### What bit while writing it

- **`point-max` is not the end of the prompt.** It is the end of the read-only
  footer. The editable region ends at `ecc-chat-prompt-end`; inserting at
  `point-max` signals `Text is read-only`.
- **macOS creates the GUI frame at the very end of startup.** Nothing loaded with
  `-l` can size, position or dress the frame; it has to be deferred, which is
  what the `window-setup-hook` and `run-at-time` at the bottom of the script are
  for. Run through the binary rather than `open` and you get a terminal frame
  instead of a graphical one.
- **`frame-position` there is the outer window, title bar included**, so the
  frame rectangle is exactly what `screencapture -R` should be given. Adding an
  offset for the title bar captures a strip of whatever is behind the window.
- **`open` does not pass the environment on**, because it goes through
  LaunchServices. The wrapper hands paths in with `--eval` instead.
- **`read` returns non-zero at EOF without a newline**, which `set -e` takes as a
  failure and kills the script silently. The geometry file ends in a newline for
  this reason.
- **Double quotes in a prompt do not survive the trip** through `emacsclient -e`
  in the shell driver. Keep demo prompts free of them.
- **Filtering a line out of a fixture shifts every number after it.** The step
  ranges in the driver are indices into the *filtered* list, and the comment
  above them says what each index is.

Anything on screen is published, so keep the demo in English and keep real paths
and personal directories out of frame.
