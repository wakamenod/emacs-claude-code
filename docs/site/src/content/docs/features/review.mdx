A review shows changes as one read-only diff, however they were made: an edit, a shell command or a script. You comment on lines or hunks, and `C-c C-c` sends every comment to the session as one prompt. The same review opens [in ediff](/emacs-claude-code/features/review-ediff/), and [Claude can comment in it](/emacs-claude-code/features/review-claude/) too.

## Choosing what to compare

`C-c c D` (`ecc-review-menu`) asks what to compare. Each line shows how many files that review would show, and the menu marks your last choice with `(last)`, so `RET` opens it again.

| Key | Compares |
|---|---|
| `D` | Everything since the session started |
| `w` | Uncommitted changes, staged or not, against `HEAD` |
| `u` | Unstaged changes |
| `s` | Staged changes |
| `b` | This branch against another |
| `p` | A GitHub pull request (only when the `gh` CLI is on `PATH`) |
| `c` | One commit, or a run of commits |
| `r` | A range you type |
| `S` | Switch the menu to another session and its project |
| `-f` | Choose the files to keep |
| `-e` | Open this one review in ediff (or as a diff when `ecc-review-style` is `'ediff`) |

The review is of the current buffer's project, and the comments go to its session; with none, ecc offers to start one. `S` chooses another session, or `+ new session`. Outside a Git repository only `D` is offered. A count that fails shows `?`, and the echo area says why.

The count beside `D` takes a snapshot of the working tree. To leave it out, set `ecc-review-menu-count-session-changes` to `nil`.

### A branch, a commit, a pull request

`b` asks for the base. The default is the branch you most likely started from, and each candidate shows how far it is from its upstream, as in `develop  (4 behind origin/develop)`. It then asks for the other side. The default, the current branch with its working tree, includes uncommitted and untracked files and is named `develop + working tree`. Another branch shows `BASE...BRANCH`, as a pull request does.

`c` asks for a commit, then for the last commit to include. `RET` at the second question reviews the one commit; a second commit reviews both and every commit between them. The list holds the last 2000 commits. For another one, type its full hash, a tag or any revision git resolves, such as `HEAD~3000`. Fetch it first if your repository does not have it yet.

`p` lists the open pull requests, with the open pull request of your branch as the default. A number opens any pull request, merged and closed ones included. The first entry, `Search pull requests…`, searches every pull request, closed and merged ones too, in GitHub's search syntax such as `is:merged author:someone` or `label:bug`. Words you type that match no entry are searched too. A completion UI that keeps the first candidate selected needs its own key to submit the words as typed (`M-RET` in vertico, `M-j` in icomplete and fido, `C-M-j` in ivy), or choose the search entry before typing. Results mark `[closed]` and `[merged]`. The diff comes from your local git, which has whole files. ecc fetches only the commits that are missing, creates no branch, and leaves `HEAD` and your files alone. Your own branch's pull request opens the same review as `b`, against your working tree.

### A pull request, one commit at a time

After you choose a pull request, `p` asks which of its commits to review, oldest first. `RET` reviews the whole pull request, and choosing a commit reviews that commit alone. Merge commits and commits that change no file are not offered.

In a review opened from `p`, `]` opens the next commit in the same window and `[` the previous one. From the whole pull request, `]` opens its first commit. The header line (in ediff, the right window's mode line) shows the commit, as in `#124 commit 2/5`, and how many unsent comments the other commits hold. Each commit keeps its comments while you move between them. `C-c C-c` sends the comments of the commit you are on. `C-c C-a` sends the comments of every commit as one prompt, grouped by commit, and closes those reviews.

### When the changes are not on disk

When the right side is a commit rather than your working tree (somebody else's pull request, another branch, an older commit), the header line says so (in ediff, the right window's mode line), as in `the right side is a1b2c3d, not checked out here`. The prompt your comments go in tells Claude the changes are not in the working tree and to ask before editing anything.

## Reviewing session changes

`D` in the menu (`C-c c D D`), or `M-x ecc-review`, compares the working tree with what it held when the session started, recorded without touching the index or your files. Work in progress from before is left out, changes the session committed are still shown, and a resumed session keeps its starting point.

<Video name="review" label="Every change of the session as one diff: a comment attached to a hunk, and the prompt it becomes shown before it goes" />

Another session working in the same directory shows up here too; separate [worktrees](/emacs-claude-code/features/spaces/#worktrees) keep sessions apart. A file larger than `ecc-review-max-bytes` (200,000) is named rather than printed. Outside a Git repository, a file is compared with what the CLI reported it holding before the session's first change.

| Key | Action |
|---|---|
| `c` | Comment on the line at point, or on the whole hunk from its `@@` line (again to edit it) |
| `{` / `}` | Previous / next comment |
| `l` | Jump to a comment |
| `d` | Remove a comment on this line (`C-u d` offers every comment) |
| `a` | Show or hide Claude's comments |
| `s` | Show or hide the list of files |
| `/` | Keep only the files that match a filter |
| `T` / `t` / `M` | [Talk to Claude](/emacs-claude-code/features/review-claude/#talking-to-claude-from-the-review): a tour, its next stop, a message |
| `e` | Edit the proposed content (reviewing one proposal) |
| `g` | Read the diff again |
| `]` / `[` | Next / previous commit of a [pull request](#a-pull-request-one-commit-at-a-time) |
| `C-c C-c` | Send your comments as a prompt (`C-u C-c C-c` to edit it first) |
| `C-c C-a` | Send the comments of every commit of the pull request |
| `C-c C-k` | Drop the review and its comments |
| `q` | Bury the buffer |
| `?` | List every key of the review |

The buffer is in read-only `diff-mode`: `n` and `p` move between hunks, `N` and `P` between files, and `RET` jumps to the source.

A comment on a removed line (`-`) is about the old side; on an added or context line, the new side; on the `@@` line, the whole hunk. It appears under its line as `▎ #3 text`, and the header line counts the comments.

## Following the files

An open review reads the diff again when a tool of its session finishes, when a turn ends, and when you save a file of its repository. Your comments and your place are kept, as with `g`. A review out of sight is read when you show it again. When every change has gone, for example because it was committed, the review stays open and says so.

Comments follow their lines. A comment whose line is gone is marked `[outdated]`, shown above the first hunk of its file, and still sent.

To read the diff only with `g`:

```elisp
(setq ecc-review-auto-refresh nil)
```

## Listing and filtering the files

`s` shows the files of the review in a list left of the diff:

```
 Files (3 of 5)  /review
▸ M ecc-review.el        +12 −4  2·1
  M ecc-review-ediff.el   +6 −2
  A ecc-review-files.el    +80  0·1!
```

Each line shows what happened to the file (`M` changed, `A` added, `D` deleted, `R` renamed), the lines added and removed, and the comments as `yours·Claude's`. `!` marks a file with an outdated comment, and `▸` the file you are reading.

| Key in the list | Action |
|---|---|
| `RET`, click | Go to that file in the review |
| `o` | Open the file in ediff at its first change, in a frame of its own |
| `n` / `p` | Show the next / previous file, staying in the list |
| `/` | Filter |
| `g` | Write the list again |
| `s`, `q` | Hide the list |

Once shown, the list opens with every review until you hide it or Emacs exits. Its width is `ecc-review-files-width` (32).

`/` keeps only the files whose path or one of Claude's comments contains what you type. An empty `RET` shows every file again. Hidden files keep their comments, which `C-c C-c` still sends, and moving between hunks and comments skips them. The header line says how many files are hidden; in ediff, the right window's mode line does.

## Sending comments

`C-c C-c` sends your comments as one prompt and closes the review. `C-u C-c C-c` opens the prompt in a buffer first, where `C-c C-c` sends it and `C-c C-k` returns to the diff:

````
## hello.py  L1-L6
```diff
 def greet(name):
     """Say hi."""
-    return "hi " + name
+    return "hello " + name
```
Comment: the docstring still says hi
````

Each comment carries its whole hunk. A line comment names its line, as in `## hello.py  L3 (new)`, and an outdated one ends with `(outdated)`.

## Reviewing against a commit or a range

`w` in the menu (`C-c c D w`), or `M-x ecc-review-range`, compares the whole repository with `HEAD`: staged and unstaged changes, and untracked files that `.gitignore` does not exclude. A repository with no commits is compared with the empty tree. To give it a key of its own:

```elisp
(with-eval-after-load 'ecc-answer
  (define-key ecc-global-map "G" #'ecc-review-range))
```

`C-u M-x ecc-review-range` asks what to compare, then for the files (empty for all):

| You type | Compares |
|---|---|
| A revision, such as `HEAD~1` | It with the working tree, untracked files included |
| A range, such as `main...HEAD` or `HEAD^!` | The commits, without untracked files |
| Nothing | The index with the working tree: the unstaged changes |
| `--staged` or `--cached` | `HEAD` with the index: the staged changes |

Hunks are as small as the change, since a comment carries its whole hunk. `(setq ecc-review-context-lines 3)` widens them. A proposal keeps three lines either way (`ecc-review-proposal-context-lines`).

## Where a review opens

| Variable | Default | Values |
|---|---|---|
| `ecc-window-hide-on-review` | `nil` | `'project` hides this project's sessions, `'all` every session, `nil` none |
| `ecc-window-review-focus` | `'review` | `'review` selects the review, `'session` keeps point in the transcript, `nil` leaves it where it was |

Hidden windows do not come back by themselves. `C-c c V` lays the Space out again (with Spaces off, `M-x ecc-focus-project`), and `C-c c v` brings back one session.
