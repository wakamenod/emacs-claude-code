ecc は `claude` をヘッドレスで動かし、その stream-json プロトコルでパイプ越しに
やりとりし、会話を普通の Emacs バッファに描きます。ターミナルエミュレータはどこ
にも使っていません。

パッケージの他のすべてはこの一つの決定から出てきています。それで何が手に入り、
何を諦めることになるのかを、はっきりさせておく価値があります。

## トランスクリプトはテキストである

レンダラーがバッファに入れるのは、フェイスの付いたテキストです。ウィジェットは
一つもなく、会話の画像でもありません。だから Emacs がテキストに対してすでにでき
ることは、ecc が何か用意しなくてもそのまま効きます。

- 会話全体に対する `isearch` と `occur`
- ターンへの narrowing
- `M-w` でのコードブロックのコピー。モデルが書いたそのものが取れます
- ファイルにしたいときの `ecc-session-export-markdown`

構造はセクションライブラリではなくテキストプロパティで持っています。見出し行は
自分がどのノードのもので深さがいくつかを知っていて、畳むのは本体に `invisible`
をかけたオーバーレイ、トランスクリプトの一文字キーはそのテキストに乗った
`keymap` プロパティから届きます。セッションバッファでは font-lock を切ってあり、
フェイスは挿入時に付けます。長い会話を画面に置いておいてもコストがかかりません。

## 一つのバッファ、二つの領域

セッションバッファは、上にトランスクリプト、区切り線の下に入力するプロンプト領
域を持ちます。プロンプトの下にはフッターがあり、そのセッションが今どの権限モー
ドで動いているかを示します。

この二つの領域は**別のキーマップ**に従います。これが何より先に知っておくべきこ
とです。トランスクリプトは読み取り専用で、一文字がそのまま操作になります（`n`、
`p`、`TAB`、`a`、`d`）。プロンプト領域には keymap プロパティがないのでメジャー
モードのキーマップが効き、そちらは `RET`、`TAB`、`C-c` 配下しか束縛していませ
ん。入力している間、文字は文字のままです。

再描画はプロンプト領域より先には決して及びません。書きかけの下書きは、その間に
セッションが何をしようと残ります。終わったターンも二度と触りません。再描画は今
のターンだけを組み直すので、コストが会話の長さに比例して増えることがありません。

## やらないこと

- **ターミナル UI は持たない。** ecc は CLI のターミナルインターフェースを作り直
  しません。それが必要になったら `ecc-tui-open` が動いているセッションを本物の
  ターミナルクライアントに渡し、`ecc-tui-return` が引き取ります。二つ目の窓では
  なく、持ち手の交代です。CLI にロックはなく、一つのセッションに二つのプロセスが
  つくと、記録に黙って二本目の枝が生えます。
- **Claude Code 専用。** ecc はこの CLI のプロトコルを直接話します。汎用の LLM
  フロントエンドではありませんし、解釈する形は実物の CLI から
  `test/fixtures` に録ったものです。
- **描画器は小さい。** Markdown、表、diff は `markdown-mode` や外部の `diff` で
  はなく ecc 自前のパーサが描きます。意図してささやかなもので、バッチテストでも
  `diff` の入っていないマシンでも同じ結果になります。
- **推測しない。** 権限リクエスト、使用量、過去の会話は、ecc の推測ではなく CLI
  が報告したものです。ecc が知らないメッセージも捨てられません。トランスクリプ
  トに `unknown` ノードとして、そしてセッションのログバッファに残ります。

## 既定は安全側

- 権限プロンプトの既定は**拒否**です。急いでキーを押したせいで何かが走ることはあ
  りません。
- Claude が Emacs にしか分からないことを訊けるループバック MCP サーバーは、自分
  で有効にするまで**止まっています**。
- そのサーバー経由の Elisp 評価には、**もう一段**の明示的な有効化が要ります。
- まだ生きているセッションの再開は確認を取ります。会話が分岐するからです。
