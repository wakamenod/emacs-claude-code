セッション内で `C-c ?`、あるいはどこからでも `M-x ecc-menu` を実行すると、キー
を割り当てる価値のあるコマンドすべてに届く transient メニューが 1 つ開きます。
このページはそのメニューをグループごとになぞり、メニューではなくモードマップに
だけあるコマンドを補います。

各コマンドにはメニューのキーを添えてあります。`C-c ?` に続けて `c` でセッション
が始まります。

## Session

| キー | コマンド | 何をするか |
|---|---|---|
| `c` | `ecc-start` | ディレクトリを指定し、名前をつけてセッションを開始する。autoload されているので、ecc の読み込み前でも `M-x ecc-start` が使える |
| `r` | `ecc-resume` | `--resume` でセッションを再開する。`-f` スイッチでフォークする |
| `k` | `ecc-kill` | セッションを停止し、忘れる |
| `R` | `ecc-rename-session` | セッションの名前を変え、そのバッファ名もあわせて変える |
| `v` | `ecc-show-session` | このバッファが結びついているセッションを表示し、そのプロンプトへ移動する |
| `w` | `ecc-toggle` | このプロジェクトのセッションウィンドウを隠す、または隠したものを戻す |
| `S` | `ecc-switch-session` | タブをクリックしたときのように、このウィンドウに別のセッションを表示する |
| `i` | `ecc-interrupt` | 実行中のターンを中断する |
| `t` | `ecc-tui-open` | 本物のターミナル UI でセッションを続ける |
| `u` | `ecc-tui-return` | ターミナルから取り戻し、ふたたび Emacs で動かす |

`ecc-toggle-all` は、このプロジェクトだけでなくすべてのプロジェクトのセッション
ウィンドウを隠す／戻します。メニューには載っていません。`w` の前に `C-u` を打て
ば同じことができ、メニューは開いたまま前置引数を保持します。

:::caution[生きているセッションを resume するとフォークします]
まだ生きているセッションに対して 2 つめのプロセスが `--resume` を実行すると、会
話がフォークします。それを止めるロックはありません。先にセッションを停止してく
ださい。`ecc-history-resume` は実行前に確認します。
:::

## Send

この多くはトランスクリプトではなく、ふつうのソースバッファから使うものです。
エディタの中にクライアントを置くことの眼目がここにあります。すなわち、CLI が知
らずに Emacs が知っていることです。

| キー | コマンド | 何をするか |
|---|---|---|
| `s` | `ecc-send` | ミニバッファで打った 1 行を送る。プレフィックス引数でどのセッションか尋ねる |
| `x` | `ecc-send-with-context` | 現在のバッファのファイルと行を添えてテキストを送る |
| `g` | `ecc-send-region` | リージョン、またはバッファ全体を引用して送る。プレフィックス引数でその前に置く指示を尋ねる |
| `f` | `ecc-send-buffer-file` | このバッファのファイルを `@path` 参照として送る |
| `e` | `ecc-fix-error-at-point` | ポイント位置の診断を直すよう Claude に頼む |
| `l` | `ecc-inline-prompt` | リージョンまたはこのファイルについて尋ね、その場のオーバーレイに答えさせる |
| `W` | `ecc-rewrite` | 指示のとおりにリージョンを書き換える。回答は表示されるだけで、受け入れるまで何も書き込まれない |
| `/` | `ecc-slash-command` | 補完で選んだスラッシュコマンドを送る |

スラッシュコマンドは `/` の下に専用のサブメニューとして並びます。中身はセッショ
ンが「持っている」と申告したものから組み立てられます。プロンプト領域で `/` を打
つのも同じことです。

`ecc-btw-ask` は、Claude がしていることを邪魔せずに脇から質問します。ターミナル
クライアントの `/btw` にあたるものです。`ecc-btw-show` は尋ねた内容を表示しま
す。どちらもメインメニューにはなく、後者にはセッション内の `C-c C-b` で届きま
す。そのパネルで `a` を押せば次の質問を投げられます。

## Review

| キー | コマンド | 何をするか |
|---|---|---|
| `D` | `ecc-review` | セッション中の変更すべてを 1 つの diff として開き、レビューする |
| `F` | `ecc-goto-files` | Files セクションへ移動する |
| `P` | `ecc-goto-plan` | Plan セクションへ移動する |
| `T` | `ecc-timeline` | このセッションのターンを選ぶ |

`ecc-session-export-markdown`（`C-c C-e`）は会話を Markdown として書き出しま
す。トランスクリプトはふつうのバッファテキストなので、`occur`、`isearch`、
narrowing は ecc の助けなしにそのまま効きます。

## Respond

このグループのキーは `A` を除いてすべて `ecc-global-map` にも同じ文字で入ってい
るので、どのバッファからでも使えます。
[キーバインドリファレンス](/emacs-claude-code/ja/reference/key-bindings/)を参照
してください。

| キー | コマンド | 何をするか |
|---|---|---|
| `a` | `ecc-answer-allow` | 最も古い待機中リクエストを許可する |
| `A` | `ecc-perm-allow-all` | このセッションで待機中のリクエストをすべて許可する |
| `d` | `ecc-answer-deny` | 最も古い待機中リクエストを、理由を添えて拒否する |
| `n` | `ecc-next-attention` | セッションをまたいで、次の待機中リクエストへ移動する |
| `N` | `ecc-next-attention-in-project` | 同じだが、現在のプロジェクトに限る |
| `1`–`4` | `ecc-answer-option-N` | 最も古い質問に選択肢 N で答える |

このうち 2 つはスイッチを伴います。メニューの `-f` と `-r` の行がそれです。`-r`
は `A` を「待機中をすべて許可し、**以後それらのツールについて訊かない**」に変え、
`-f` は Session グループの `r` をフォークに変えます。スイッチは実行前に設定し、
状態が画面に出ます。とりわけフォークに向いた形です。生きているセッションに 2 つめ
のプロセスが `--resume` すると会話がフォークし、それを止めるロックはありません。

権限の問い合わせは**既定で拒否**です。セッション内では `ecc-perm-allow` と
`ecc-perm-deny` がポイント位置のリクエストに答え、`ecc-perm-allow-always`、
`ecc-perm-approve-turn`、`ecc-perm-add-pattern` はその答えを、同種のものすべて
へ、ターンの残りへ、あるいは与えたパターンへと広げます。

## View

| キー | コマンド | 何をするか |
|---|---|---|
| `b` | `ecc-dashboard` | この Emacs が動かしているセッションを 1 つの一覧に |
| `y` | `ecc-capabilities-show` | セッションが持つスキル、エージェント、コマンド、MCP サーバー、プラグイン |
| `h` | `ecc-history-open` | 記録された会話をセッションバッファに開く |
| `U` | `ecc-usage` | Claude Code プランをどれだけ使ったか |
| `L` | `ecc-show-log` | このセッションの生プロトコルログ |

`ecc-history-open` は、CLI が `~/.claude/projects` の下に書いたものを読み戻しま
す。この記録はリストではなく木です。編集、中断、再開はいずれも枝を生やします。
放棄された枝は畳まれますが、`/compact` は新しい根を始めるので、放棄されたものと
は決して見なされません。

ダッシュボードに並ぶのは**この Emacs が動かしているセッション**だけです。モデ
ルから読んでいるので常に最新で、ポーリングするものが何もありません。別のプロセ
スが動かしているセッションはここからは答えも操作もできませんし、記録でしかない
会話はそもそも動いていません。そのどちらにも `ecc-history-open` と `ecc-resume`
から届きます。この二つはある限りの記録を差し出します。CLI が自分自身について
`~/.claude/sessions` の下に書くファイルを読むのは `ecc-registry` で、再開する前
にセッションがまだ生きていると分かるのはそのおかげです。

## Config

| キー | コマンド | 何をするか |
|---|---|---|
| `m` | `ecc-set-model` | このセッションに別のモデルを使うよう頼む |
| `p` | `ecc-set-permission-mode` | このセッションに権限モードの切り替えを頼む |
| `o` | `ecc-remote-control-toggle` | このセッションの Remote Control をオン／オフする |
| `O` | `ecc-remote-control-open` | このセッションを claude.ai/code で開く |
| `K` | `ecc-remote-control-copy-url` | その URL を kill リングに入れる |
| `C` | `ecc-customize` | カスタマイズグループを開く |

`ecc-set-model` は動いているセッションのモデルを再起動なしに変えます。モデルを
指定する設定がないのはそのためです。セッション内の `S-TAB` は、メニューを経由せ
ずに権限モードを順に切り替えます。

## MCP サーバー

| コマンド | 何をするか |
|---|---|
| `ecc-mcp-start` | MCP サーバーを起動し、待ち受けているポートを返す |
| `ecc-mcp-stop` | 停止する |

ふだんはどちらも要りません。`ecc-mcp-enabled` を設定しておけば、最初に必要とす
るセッションが現れた時点でサーバーが起動します。
[設定リファレンス](/emacs-claude-code/ja/reference/configuration/#mcp-サーバー)
を参照してください。
