変更を 1 つの diff として確認し、手を入れたいハンクにコメントを付け、すべてのコメントを 1 つのプロンプトで送信できます。同じバッファで、セッションが変更した内容、セッションが手を入れた作業ツリー、適用前の 1 つの提案をレビューできます（[提案とプランモード](/emacs-claude-code/ja/features/approval/)）。

`C-c c D` で開くメニューで、何と比べるかを選びます。よく使う 2 つのレビューは同じもので、比較の基準だけが違います。

- メニューの `D` — **セッションを開始した時点**との差分。セッション中にコミットした変更も表示されます。
- メニューの `w` — **直前のコミット（`HEAD`）** との差分。未コミットの変更だけが表示されます。

どちらも、ファイルがどう変更されたかを問いません。編集、シェルコマンド、スクリプトのどれによる変更も同じように表示されます。

## 比べる対象を選ぶ

`C-c c D`、または Transient メニューの `D` で `ecc-review-menu` が開きます。何かを開く前に比べる対象を選ぶメニューで、各行にはそのレビューに出るファイルの数が表示されます。

| キー | 比べる対象 |
|---|---|
| `D` | セッション開始以降のすべての変更（[後述](#セッション全体の変更をレビューする)） |
| `w` | ステージの有無を問わず、`HEAD` に対する未コミットの変更。`M-x ecc-review-range` と同じ |
| `u` | 未ステージの変更 |
| `s` | ステージ済みの変更 |
| `b` | このブランチと別のブランチ |
| `p` | GitHub のプルリクエスト。`gh` CLI があるときだけ表示 |
| `c` | 1 つのコミット、または連続したコミット |
| `r` | 手で入力した範囲。`C-u M-x ecc-review-range` と同じ形式 |

git の項目（`w`〜`r` と `p`）は、カレントバッファのプロジェクトをレビューし、コメントをそのプロジェクトのセッションに送ります。プロジェクトにまだセッションがなければ、起動するかを尋ねます。`D` はそのセッションをレビューします。プロジェクトにセッションがなければ、最後に使ったセッションをレビューします。見出しにはセッションとプロジェクトが表示されます。`S` はメニュー全体を別のセッションとそのプロジェクトに切り替えます。候補には今のプロジェクトのセッションが先に並びます。そのため、あるプロジェクトを比べてコメントを別のプロジェクトに送ることはありません。先頭の候補 `+ new session` は、メニューのプロジェクトで新しいセッションを起動し、コメントをそこへ送ります。新しいセッションはレビューのツールを持つので、すぐに `T` を使えます。`-f` を付けると、比べる対象を選んだあとに、残すファイルを尋ねます。`-e` を付けると、そのレビューだけを ediff で開きます（`ecc-review-style` が `'ediff` なら diff で開きます）。設定は変わりません。Git リポジトリの外では `D` しか選べず、メニューにその理由が表示されます。前回選んだ項目には `(last)` が付き、ポイントもそこに置かれるので、`RET` で同じレビューをもう一度開けます。件数を数えられなかった行には `?` が表示され、理由がエコーエリアに出ます。

`b` では、まず比べる元（変更前の側）を尋ねます。デフォルトは、今のブランチの分岐元として最も可能性が高いブランチです。候補は `develop`、`main`、`master` と、`origin/HEAD` が指すブランチです。今いるのがこれらのブランチなら、その upstream も候補になります。そのため `main` では `origin/main` がデフォルトになり、まだ push していないコミットが表示されます。`HEAD` より先に進んでいる候補は外します。`main` にいて、`develop` のほうが先に進んでいるときの `develop` がその例です。`HEAD` と同じ位置にある候補は残します。今のブランチを作ったばかりの元のブランチだからです。残った候補のうち、`HEAD` までのコミット数が最も少ないものを選びます。それが upstream より遅れていて、自分のコミットを持たないローカルブランチなら、デフォルトは upstream になります。ローカルの `develop` が `origin/develop` より 4 コミット遅れていると、まだ pull していないコミットがレビューに入ってしまうためです。候補が残らなければ、`b` はデフォルトなしでブランチを尋ねます。一覧の各ブランチには、`develop  (4 behind origin/develop)` のように upstream との差が表示されます。

次に、変更後の側を尋ねます。デフォルトは今のブランチと作業ツリーです。この場合、2 つのブランチが分かれたコミットと今のファイルを比べるので、未コミットの変更と未追跡のファイルもレビューに入ります。レビューのバッファ名は `develop + working tree` のように比べる元から付き、同じ選択をもう一度開くと同じバッファを使います。Claude が `review_open` で同じ比較を開いたときもこのバッファを使うので、Claude のコメントは今読んでいるレビューに付きます。別のブランチを選ぶと、プルリクエストと同じく `BASE...BRANCH` の差分を表示します。

`c` では、最近の履歴からコミットを 1 つ選び、続けて含める最後のコミットを尋ねます。2 つ目の質問で `RET` を押すと、そのコミットだけをレビューします（`X^!`）。2 つ目のコミットを選ぶと、2 つのコミットとその間のすべてのコミットをレビューします（`X^..Y`）。どちらを先に選んでもかまいません。リポジトリの最初のコミットには親がないので、空のツリーと比べます。レビューの名前は、自分と Claude のどちらが開いても、短いコミット ID と件名から付きます。`HEAD` が動いても、同じコミットをレビューし続けます。

`p` は、`gh` CLI が `PATH` にあるときだけ表示されます。ecc は gh に依存しておらず、メニューを開くだけでは何も実行しません。`p` を押すと、gh にプロジェクトのリポジトリのオープンなプルリクエストを尋ねます。それを gh の順のまま `#113  fix(review): …  fix/x → develop  @someone` のように並べます。ドラフトには印が付きます。デフォルトは、今チェックアウトしているブランチのプルリクエストです。一覧にないもの（マージ済みのものなど）は、番号を入力すればレビューできます。ログインしていない、GitHub のリモートがないなどの理由で gh が失敗したときは、gh のメッセージがエラーに表示されます。

差分は `gh pr diff` ではなく手元の git で作ります。そのためレビューにはファイル全体があり、ediff でも開けます。`-f`、`-e`、コメント、送信もいつもどおり使えます。別のブランチのプルリクエストは、コミット ID で `BASE...HEAD` を比べます。GitHub が変更として表示するファイルと同じで、レビューの名前は `PR #N タイトル` になります。手元にないコミットがあれば、足りないものだけを対応するリモートから fetch します。まずプルリクエストの head（`pull/N/head`。フォークからのものにもあります）を取り、それでもベースのコミットがなければベースブランチを取ります。ベースブランチが削除されたマージ済みのプルリクエストでも、head がベースのコミットを含んでいれば開けます。fetch が書くのは `FETCH_HEAD` だけで、ブランチや ref は作らず、`HEAD` とファイルには触れません。今チェックアウトしているブランチのプルリクエストは、今のブランチを選んだ `b` と同じようにレビューします。ベースと分かれたコミットを作業ツリーと比べ、名前も `b` と同じ `develop + working tree` になるので、どちらから開いても同じレビューです。まだ push していない変更も入り、行が Claude の編集するファイルと一致します。

### 変更がディスクにないとき

コメントは、ディスク上のファイルを編集する Claude のセッションに送られます。レビューの右側が作業ツリーではなくコミットのとき、たとえば他人のプルリクエスト、別のブランチを選んだ `b`、古いコミットの `c`、2 つのコミットの `r` では、その行は手元のファイルにありません。そのときは、ヘッダー行に `the right side is a1b2c3d, not checked out here` と表示されます。プルリクエストの head なら `fix/x (a1b2c3d)` のようにブランチ名が付くので、何をチェックアウトすればよいかわかります。ediff では右のウィンドウのヘッダー行の末尾に表示されます。コメントを送るプロンプトにも、変更が作業ツリーにないこと、何かを編集する前に確認すること、自分ではチェックアウトしないことを Claude に伝える一文が加わります。右側が `HEAD` のコミットなら、手元のファイルがそのコミットなので何も表示しません。

`D` の件数を数えるには作業ツリーのスナップショットが必要です。300 ファイルのリポジトリで 35 ms、20,000 ファイルのリポジトリで 70 ms かかりました。ほかの件数は 1 回の `git status` から数えます。`D` の件数を省くには、`ecc-review-menu-count-session-changes` を `nil` にしてください。

## セッション全体の変更をレビューする

レビューのメニューで `D` を押すか（`C-c c D D`）、`M-x ecc-review` を実行します。一部のファイルだけをレビューするには、メニューで `-f` を付けるか、`M-x ecc-review` にプレフィクス引数を付けます。

<Video name="review" label="セッション全体の変更を 1 つの diff で表示し、ハンクにコメントを付け、送信前にそのプロンプトを確認する様子" />

セッションが始まると、ecc はその時点の作業ツリーの内容を記録します。使い捨てのインデックスを通して Git のツリーオブジェクトを書き出すので、何もスタッシュせず、実際のインデックスとファイルには触れません。レビューは今のツリーをこのベースラインと比べます。そのため、セッションの前から進めていた作業はレビューに入りません。また、CLI が編集ツール、シェルコマンド、スクリプトのどれで変更しても、その変更は表示されます。

基準はコミットではなく時点なので、セッションの途中でコミットした変更も表示されます。`HEAD` に対するレビューでは、これが見えなくなります。セッションを再開しても、ベースラインは変わりません。

基準は時点であって作成者ではないので、同じディレクトリで動く別のセッションの変更もここに表示されます。Git の worktree を分ければ混ざりません。`ecc-review-max-bytes`（デフォルト 200,000）を超えるファイルは、中身ではなく名前だけを表示します。パッケージマネージャーが書き直したロックファイルは、たいていこれに当たります。

Git リポジトリの外には比べるツリーがないので、セッションが最初に変更する前の内容として CLI が報告したものとファイルを比べます。以前の動作が残っているのはここだけです。

| キー | 動作 |
|---|---|
| `c` | ポイントのある行にコメント。`@@` 行ではハンク全体にコメント（もう一度押すと編集） |
| `{` / `}` | 前 / 次のコメントへ移動 |
| `a` | Claude のコメントの表示・非表示を切り替え |
| `l` | コメントへジャンプ |
| `d` | この行のコメントを削除。自分のものも Claude のものも消せる（`C-u d` ですべてのコメントから選ぶ） |
| `s` | ファイルの一覧の表示・非表示（[ファイルを一覧し絞り込む](#ファイルを一覧し絞り込む)を参照） |
| `/` | フィルタに合うファイルだけを残す |
| `T` / `t` / `M` | Claude に案内を頼む、その次の箇所を頼む、メッセージを送る（[レビューから Claude と話す](#レビューから-claude-と話す)を参照） |
| `e` | 提案内容を編集（1 つの提案のレビュー時） |
| `C-c C-c` | 自分のコメントをプロンプトとして送信（`C-u C-c C-c` で送信前に編集） |
| `C-c C-k` | レビューとコメントを破棄 |
| `g` | diff を読み直す（[ファイルの変更に追従する](#ファイルの変更に追従する)を参照） |
| `q` | バッファを隠す |
| `?` | レビューのキーをすべて表示 |

バッファは読み取り専用の `diff-mode` です。`n` と `p` でハンク間を、`N` と `P` でファイル間を移動し、`RET` でソースへジャンプします。この 4 つは、フィルタで隠したファイルを飛ばします。

コメントは、付けた行に属します。削除行（`-`）では変更前の側、追加行（`+`）と文脈行では変更後の側についてのコメントです。`@@` 行ではハンク全体へのコメントです。コメントは行の下に `▎ #3 本文` の形で表示され、そのハンクのヘッダーは太字になり、ヘッダーラインにはコメントの数が出ます。コメントにはそれぞれ番号が付き、1 つのバッファで番号が重なることはありません。

`g` は diff を読み直し、コメントと読んでいた位置をすべて保ちます。別のタブにあるレビューのウィンドウは先頭に戻ります。各コメントは、元の行と同じ内容で、前後の行も同じ行に戻ります。ファイルの上のほうの変更で行がずれていても同じです。追いかけるのは `ecc-review-note-max-shift`（デフォルト 100）行までです。ハンク全体へのコメントはハンクについていきます。まず `@@` 行で探し、見つからなければ、そのハンクが覆う変更前の行で探します。変更前の行は、上に行が追加されても動きません。行がなくなったときもコメントは残り、`[outdated]` の印を付けて、そのファイルの最初のハンクの上に表示します。このコメントも送信され、元のハンクと一緒に送られます。

## ファイルの変更に追従する

開いているレビューは、ファイルに変更があり得るときに diff を読み直します。そのセッションのツールが終わったとき、ターンが終わったとき、Emacs でそのリポジトリのファイルを保存したときです。編集だけでなく、シェルコマンドやスクリプト、同じリポジトリで動く別のセッションによる変更も対象です。Read や Grep のように読むだけのツールは対象外です。`g` と同じく、コメントと読んでいた位置は保たれます。

レビューは 0.5 秒待ち（入力中はもっと待ちます）、続けて起きた変更をまとめて読みます。diff が変わっていなければ、バッファはそのままです。読み直すのは画面に出ているレビューだけで、見えていないレビューは次に表示したときに読み直します。レビューはフォーカスを取らず、ウィンドウを動かさず、入力中のプロンプトにも触れません。コミットなどで変更がすべてなくなっても、レビューは開いたままで、その旨を表示します。そのレビューで `g` を押しても、表示するものがないと伝えます。ディレクトリが消えたなどで diff を読めないときは、ヘッダーラインに理由を表示し、`g` を押すまで待ちます。1 つの提案のレビューは読み直しません。

ediff のレビューも同じようにファイルの変更に追従します。今いる差分と、左右それぞれが表示している行は保たれます。ecc が読めなかったときは、`!` で読み直せます。[ediff でレビューを開く](#ediff-でレビューを開く)を参照してください。

この追従を止め、`g` を押したときだけ読み直すには次のようにします。

```elisp
(setq ecc-review-auto-refresh nil)
```

## ファイルを一覧し絞り込む

`s` を押すと、レビューのファイルの一覧を diff のすぐ左に表示します。ファイルの多いレビューでも、各ファイルに何が起きたか、どれだけ変わったか、コメントがどこにあるかをひと目で見渡せます。diff バッファで使えるほか、ediff のレビューでは左右どちらのウィンドウからも、コントロールパネルからも使えます。

```
 Files (3 of 5)  /review
▸ M ecc-review.el        +12 −4  2·1
  M ecc-review-ediff.el   +6 −2
  A ecc-review-files.el    +80  0·1!
```

各行の先頭は、ファイルに何が起きたかを表します。`M` は変更、`A` は追加、`D` は削除、`R` は名前の変更で、`R` には元の名前も付きます。続いて追加と削除の行数、自分と Claude のコメント数が `自分·Claude` の形で並びます。古くなったコメントがあるファイルには `!` が付きます。`▸` は読んでいるファイル（diff バッファではポイントのあるファイル、ediff では現在の差分のファイル）を示し、移動に合わせて動きます。

一覧では、`RET` かクリックでそのファイルへ移ってレビューに戻り、`o` でファイルそのものを開きます。ediff では最初の変更の位置で、専用のフレームに開きます。`n` と `p` は次・前のファイルを表示し、ポイントは一覧に残ります。`/` で絞り込み、`g` で一覧を書き直し、`s` か `q` で一覧を隠します。

一覧はいつも diff の左に出ます。ediff ではレビューがフレームを占めるので、一覧はフレームの左端のサイドウィンドウになり、`|` や `m` を使っても位置は変わりません。`ecc-review-ediff-full-frame` が `nil` のときは、代わりにレビューの左側を分割して一覧を出します。diff バッファでは、レビューのウィンドウの左側を分割して出します。一覧を隠すと、その幅は diff に戻ります。`q` などでレビューがウィンドウから離れると、一覧も閉じます。ウィンドウが狭くて一覧が入らないときは、一覧なしでレビューを開きます。`/` はそのまま使えます。

最初、一覧は隠れています。`s` で表示すると、そのあとに開くレビューにも表示されます。もう一度 `s` を押すか Emacs を終了するまで、この状態が続きます。幅は `ecc-review-files-width`（デフォルト 32 桁）です。

```elisp
(setq ecc-review-files-width 40)
```

ecc は、レビューを読み直すたびと、コメントが増減するたびに一覧を書き直します。

`/` を押すと、パス、元のパス、Claude のコメントのいずれかに入力した文字列を含むファイルだけを残します。大文字と小文字は区別しません。そのため、ファイル名だけでなく、Claude がそのファイルについて書いた内容からも探せます。入力するにつれて一覧が現れ、絞り込まれていきます。`RET` でレビューのほかのファイルを隠し、空のまま `RET` を押すとすべてのファイルを表示し直します。フィルタはファイルを隠すだけで、diff を読み直しません。隠したファイルのコメントは残り、`C-c C-c` で送信されます。diff バッファのヘッダーラインには、`/review: 2 files hidden by filter` のように隠したファイルの数が出ます。ediff では、キーボードのあるウィンドウのヘッダーラインに `/review: 2 hidden` と出ます。

移動は隠したファイルを飛ばします。diff バッファでは `n`・`p`・`N`・`P`、ediff では `n`・`p`・`j`、両方で `{` と `}` です。`review_hunks` と `review_open` は、フィルタのことを Claude に伝えます。Claude の `next_comment` と `prev_comment` も隠したファイルを飛ばし、Claude は隠したファイルまでレビューをスクロールできません。フィルタは、レビューを読み直しても残ります。

## コメントを送信する

`C-c C-c` は自分のコメントを 1 つのプロンプトにまとめて送信し、レビューを閉じます。コメントがそのままプロンプトになるので、ふつうは何も付け足さずに済みます。`C-u C-c C-c` なら、送る前に専用のバッファで開きます。

````
## hello.py  L1-L6
```diff
 def greet(name):
     """Say hi."""
-    return "hi " + name
+    return "hello " + name
```
Comment: the docstring still says hi
````

行へのコメントは `## hello.py  L3 (new)` のように見出しに行が入り、ハンク全体も載ります。行がなくなったコメントは、見出しの末尾に `(outdated)` が付きます。Claude への返信は `In reply to Claude's #4:` で始まり、返信先のコメントを引用します。

このバッファでは、`C-c C-c` でプロンプトをそのまま送信し、`C-c C-k` で diff に戻ります。

## コミットや範囲に対してレビューする

`ecc-review` がセッションの開始時点を起点にするのに対し、`ecc-review-range` はデフォルトで直前のコミットを起点にします。レビューのメニューで `w` を押す（`C-c c D w`）か、`M-x ecc-review-range` を実行します。専用のキーはありません。割り当てるには次のようにします。

```elisp
(with-eval-after-load 'ecc-answer
  (define-key ecc-global-map "G" #'ecc-review-range))
```

プロジェクトのリポジトリ全体を `HEAD` と比べます。ステージ済みかどうかを問わず未コミットの変更すべてと、未追跡のファイルが対象です。`.gitignore` で除外したファイルは入りません。バイナリファイルや `ecc-review-max-bytes` を超えるファイルは、中身ではなく名前だけを表示します。まだコミットがないリポジトリでは空のツリーと比べるので、プロジェクトで最初に書いたコードもコミット前にレビューできます。

`C-u M-x ecc-review-range` では、まず比べる対象を尋ね、次に対象のファイルを尋ねます。比べる対象として、リビジョンか、`main...HEAD` のような範囲を入力します。空のままなら未ステージの変更だけを比較します。入力ごとの比べ方は次のとおりです。

- `HEAD~1` のようなリビジョンは、作業ツリーと比較します。未追跡のファイルも含みます。
- `main...HEAD`、`HEAD~1..HEAD`、`HEAD^!` のような範囲は、コミット同士を比較します。未追跡のファイルは含みません。
- 空のままなら、インデックスと作業ツリーを比較します。
- `--staged`（または `--cached`）は、`HEAD` とインデックスを比較し、ステージ済みの変更だけを表示します。バッファ名には `staged changes` と付きます。

続けて、含めるファイルを尋ねます。補完でいくつでも選べ、空のままなら全ファイルが対象です。`g` でも[ファイルの変更への追従](#ファイルの変更に追従する)でも、この選択は保たれます。範囲が作業ツリーを含むかどうかは、文字列から判断するのではなく `git rev-parse` で決めます。`-` で始まる範囲は拒否するので、git のオプションが紛れ込むことはありません。

対象のプロジェクトはカレントバッファで決まり、コメントはそのプロジェクトのセッションに送られます。セッションがなければ、ecc が起動するかを尋ねます。ふつうはここからセッションを始めます。コメントの付け方と送信は上と同じで、2 つのレビューは別々のバッファを使います。

コメントにはそのハンク全体が含まれるので、ハンクは変更そのものと同じ大きさにしています。`(setq ecc-review-context-lines 3)` を設定すると広がります。この値は ecc が git を実行するときに `-U` として渡すので、`git config` を読み書きすることはありません。提案のレビューは、どちらの場合も `ecc-review-proposal-context-lines` によって前後 3 行のコンテキストを保ちます。

## Claude のコメント

[Emacs の MCP サーバー](/emacs-claude-code/ja/start/installation/)が有効（`ecc-mcp-enabled`）なら、レビューは双方向になります。Claude がレビューを開き、行にコメントを付け、話題にしている箇所までスクロールできます。「この変更をレビューで順に説明して」「diff をレビューしてコメントを残して」のように、ふつうの言葉で頼んでください。

Claude のコメントは `▎ #4 Claude: 本文` の形で、専用の face `ecc-review-agent-comment-face` で表示されます。Claude のコメントだけがある行で `c` を押すと、そのコメントに返信できます。返信はその下にインデントして表示されます。`a` で Claude のコメントを隠したり表示し直したりでき、隠している間もヘッダーラインは件数を数えます。`C-c C-c` で送るのは自分のコメントだけです。Claude は自分が書いた内容をすでに知っているからです。

| ツール | Claude ができること |
|---|---|
| `review_open` | セッションの変更、範囲を指定した作業ツリー、またはステージ済みの変更（`staged`）のレビューを開く。一部のファイルだけにもできる（`paths`）。またはレビューを読み直す |
| `review_hunks` | ファイルと番号付きのハンクを一覧する。ハンクの本文も付けられる |
| `review_comment` | 行（`side` は `new` か `old`）、ハンク、または別のコメントの下（`reply_to`）にコメントを置く |
| `review_comment_apply` | 複数のコメントを一度に置く。1 件でも不正なら 1 件も置かない |
| `review_navigate` | 行、ハンク、コメント、次・前のコメントまでレビューをスクロールする |
| `review_list_comments` | コメントを読む。ユーザーのコメントは、付いているハンクと一緒に読む |
| `review_remove_comment` | コメントを 1 件削除する。対応済みのユーザーのコメントも消せる |
| `review_clear_comments` | Claude のコメントを削除する。ユーザーのコメントは指定したときだけ |

`review_open` は[レビューのメニュー](#比べる対象を選ぶ)と同じ対象を開けます。Claude に「ステージ済みの変更」「このブランチ全体」「このコミットだけ」と頼むと、`s`、`b RET RET`、`c` で開くのと同じレビューが開きます。

Claude はユーザーのコメントを書いたり書き換えたりできませんが、削除はできます。ツールは呼び出したセッションのレビューにだけ作用するので、2 つのセッションが互いのレビューに触れることはありません。

ツールがキーボードを奪うことはありません。Claude が開いたり動かしたりしたレビューは、選択されないままセッションの横に表示されます。セッションのウィンドウは隠れないので、入力中のプロンプトもそのままです。レビューが今いるウィンドウを使うことも、別のタブや Space に切り替えることもありません。表示先は、同じセッションの別のレビューのウィンドウ、空いているウィンドウ、セッションのウィンドウを分割した半分の順に選びます。そのために作ったウィンドウは `q` で消えます。レビューバッファ向けの `display-buffer-alist` のルールを書いていれば、今いるウィンドウとタブに触れない限り、レビューはそのルールに従います。セッションが画面に出ていないときや、空いているウィンドウがないときは、何も前に出てきません。レビューは Claude が選んだ位置に移った状態で、バッファの中で待ちます。

これらのツールは、バッファに文字を入れてウィンドウを動かすだけで、ファイルは書きません。そのため Emacs は確認せずに許可し、トランスクリプトには呼び出しごとに `auto-allowed` と記録します。ほかのツールと同じように確認させたいときは、`ecc-review-agent-auto-allow` を `nil` にしてください。

これらのツールは、ediff で開いているレビューにも使えます。ediff では 1 つのハンクが ediff の差分 1 つに当たり、`review_hunks` は差分の番号と左右それぞれの行範囲を返します。ediff はフレームとキーボードを奪うので、Claude が ediff を起動することはありません。ediff のレビューが開いていれば `review_open` はそれを読み直し、開いていなければ `ecc-review-style` が `'ediff` でも diff バッファを開きます。

## レビューから Claude と話す

ediff のレビューはフレーム全体を使うので、読んでいる間はセッションとそのプロンプトが見えません。レビューを離れて Claude に尋ねなくても、レビューの中から Claude と話せます。次のキーは diff バッファでも ediff のレビューのどこでも使え、送り先はいつもそのレビューのセッションです。

| キー | 動作 |
|---|---|
| `T` | 変更の案内を Claude に頼む。Claude は重要な箇所から順に、各箇所を `review_navigate` で表示して説明し、注意が必要な行にコメントを付けて待つ |
| `t` | 案内の次の箇所を頼む |
| `M` | ミニバッファでメッセージを入力し、プロンプトとして送る。セッションで入力したプロンプトと同じく、Claude はどのツールも使える |

送り方は、ミニバッファで入力したプロンプトと同じです。セッションが動いている間は、プロンプトは待ち行列に入ります。案内はレビューのツールでできているので、`T` と `t` には MCP サーバー（`ecc-mcp-enabled`）が必要です。

ediff のレビューでは、diff の横の欄に、セッションの最新の返答が届くそばから表示されます。ツールの呼び出しは 1 回ごとに 1 行です。欄は、左右の差分を上下に並べているときは右に、左右に並べているときは下に出ます。

```
› Next stop.
The cache is now keyed by path, so a renamed file is read again.
  review_navigate → ecc-review-ediff.el:248
  review_comment → ecc-review-ediff.el:252: This drops the old entry
```

新しいターンが始まると、欄の中身は入れ替わります。会話の全体はトランスクリプトに残ります。Claude が許可を求めたとき、質問したとき、承認を待つプランがあるときは、欄にその要求が省略なしで表示されます。レビューで `y` を押すと答えられます。許可か拒否を選ぶか、ミニバッファで答えを選びます。欄は選択されないので、キーボードは読んでいる場所に残ります。`|` で配置を変えると欄も一緒に移り、レビューを閉じると欄も閉じます。右に出すときの幅は `ecc-review-talk-reply-width`（デフォルト 75 桁）です。下に出すときの高さは `ecc-review-talk-reply-height`（デフォルト 12 行）です。欄の横に diff の幅 80 桁を残せないほどフレームが狭いときは、欄を下に出します。高さを `nil` にすると欄を出しません。

```elisp
(setq ecc-review-talk-reply-width 90
      ecc-review-talk-reply-height 16)
```

ediff のレビューでは、`u` で欄を Claude の前の発言へ、`d` で先へスクロールします。このために欄を選択する必要はありません。欄の中では `u`・`d`・`DEL`・`SPC` で同じことができます。返答の末尾が見えている間は、Claude が書き進めるにつれて欄も末尾についていきます。これらのキーやマウスホイールで前に戻すと、欄は同じ行を表示し続けます。末尾がまた見えるか、新しいターンが始まると、再び末尾についていきます。`|` で欄が移っても、表示していた位置は変わりません。

フレーム全体を diff に使いたいときは、欄を別のフレームに出します。フレームはレビューごとに 1 つで、そのレビューを閉じると一緒に閉じます。このフレームはフォーカスを取らないので、キーボードはレビューに残り、`y` もレビューで押します。

```elisp
(setq ecc-review-talk-reply-place 'frame)
```

diff バッファではセッションが横に見えているので、欄は出ません。

## ediff でレビューを開く

`ecc-review-style` は、レビューのメニューと `ecc-review-range` で開くレビューの表示方法を決めます。メニューの `-e` で、1 回のレビューだけ切り替えられます。デフォルトの `'diff` では、前述の 1 つの `diff-mode` バッファを使います。`'ediff` にすると、代わりにファイルを左右に並べて表示します。

```elisp
(setq ecc-review-style 'ediff)
```

レビューの全ファイルを、ファイルごとではなく 1 つの ediff セッションで開きます。変更前の内容は左のバッファに、変更後の内容は右のバッファにつなげて入れます。各ファイルの前には `═══ path ═══` のような区切り行が入り、さらにその前に空行を挟むので、ファイル同士がくっつきません。すべての変更が 1 つのセッションにあるので、`n` と `p` でレビュー全体の差分を順に移動できます。ファイルの境目もそのまま越えます。比較はファイルごとに行うので、1 つの差分が次のファイルにまたがることはありません。git がバイナリと判定したファイルや、`ecc-review-max-bytes` を超えるファイルは区切り行だけになり、差分を持ちません。区切り行は `═══ photo.png (binary, not shown) ═══` のようになります。

レビューは、変更前を上、変更後を下に、どちらもフレームの幅いっぱいに並べて開き、Claude の返答の欄を右に出します。`|` で左右に並べ（欄は下に移ります）、もう一度押すと上下に戻ります。どちらの配置で開くかは `ecc-review-ediff-layout` で選びます。

```elisp
(setq ecc-review-ediff-layout 'side-by-side)   ; デフォルトは 'stacked
```

`ecc` は `ediff-split-window-function` をレビューのコントロールバッファでだけ設定するので、ほかの ediff セッションは設定済みのウィンドウ配置のままです。各ウィンドウのヘッダーラインにはキーが表示されます。どのキーもどちらのウィンドウでも使えるので、2 行で 1 つの一覧を分け合っています。

```
 n/p diff  j jump  { } comments  c comment  x delete  l list  a Claude's  s files  / filter
 RET open  T tour  t next  M message  C-c C-c send  q quit  u/d reply  v/V scroll  ! reread  ? all keys
```

左の行には読むためのキーと自分のコメントのキー、右の行には Claude、ファイルを開く、送信、終了のキーが並びます。よく使うキーほど前にあるので、ウィンドウが狭いときに欠けるのはあまり使わないキーです。右の行の末尾には常に `? all keys` が残り、狭いウィンドウではその前のキーが省かれます。左右に並べているときは、左の行をウィンドウの右端にそろえるので、2 行が真ん中で合わさります。キーボードのあるウィンドウ（下か右）のヘッダーラインの末尾には、`3/12` のような今いる位置と、フィルタで隠したものを表示します。`? all keys` と今いる位置さえ収まらないほどウィンドウが狭いときは、今いる位置を優先します。

ediff のコントロールパネルは表示しません。`?` ですべてのキーを載せたパネルを開き、もう一度 `?` で閉じます。レビューは `ediff-window-setup-function` の設定にかかわらずパネルをレビューのフレームに出すので、コントロール用のフレームは現れません。

各ファイルは、それぞれのメジャーモードで色付けされます。レビューは色付けを待たずに開き、画面に見えている部分を先に、残りを裏で色付けします。入力中は色付けを止めます。圧縮されたスクリプトのように行がとても長いファイルは色付けしません。現在の差分と、画面に見えているほかの差分では、変わった語が太字になります。その色合いは、どのテーマでも現在の差分の強調色とはっきり区別できます。

両方のバッファは読み取り専用なので、ediff のコピーコマンド `b` はここでは何もせず、`a` は代わりに Claude のコメントの表示・非表示を切り替えます。変更を読み、コメントを付けて送信すると、Claude がそのコメントから作られたプロンプトをもとにディスク上のファイルを更新します。

### 左右のウィンドウで読む

レビューを開くと、キーボードは変更後の側（下か右のウィンドウ）にあります。コントロールパネルのキーはどれも両方のウィンドウで使え、ediff がウィンドウを並べ直しても、キーボードは入力していたウィンドウに残ります。パネルと同じく数字は回数になり、`3j` で 3 番目の差分へ移ります。`SPC` は `n`、`DEL` は `p` と同じ働きです。

ポイントを動かすと、レビューもそれに合わせて動きます。ポイントが差分に入ると、その差分が現在の差分になり、濃い色、フリンジの縦線、ヘッダーラインの番号もそこへ移ります。読んでいるウィンドウはスクロールしません。反対側のウィンドウは、対応する行が画面の同じ高さに来るように動きます。片側だけでコメントや折り返しが余分な行を取っていても同じです。削除された行は、変更がそれを取り除いた位置に対応します。差分の外では、反対側のウィンドウにファイルの同じ行を表示し、現在の差分は最後に読んだ差分のままです。このとき `n` と `p` は、ポイントより下の次の差分、上の前の差分へ移ります。`C-n`、`M-<`、クリックなど、ポイントを動かすコマンドならどれでも同じです。isearch では、入力するたびではなく、`C-s` が一致した箇所で止まったときと検索を終えたときだけ、反対側のウィンドウが追従します。`C-v`、`M-v`、マウスホイールで片側をスクロールしても、今のところ反対側は動きません。`v` と `V` で両方をスクロールでき、`C-l` で左右をそろえ直します。

`RET` は、ポイントのある行を今のファイルで開きます。コミットのレビューのときや、レビューが読んだあとにファイルが変わったときは、ecc がそのあとの変更をたどって行を合わせます。左側の行は今その行がある位置に、削除された行は元あった位置に開きます。ファイルは専用のフレームに開き、そのフレームがある間は毎回同じフレームを使います。レビューのフレーム、ウィンドウ、キーボードはそのままです。

### ediff でのコメント

ウィンドウの中の `c` は、ポイントのある行にコメントを付けます。diff バッファの行で `c` を押したときと同じく、変更で削除された行なら左側、追加された行なら右側です。左右で共通の行にはコメントするものがないので、`c` はそう伝えます。`?` でコントロールパネルを表示しているときは、パネルの `c` が現在の差分全体にコメントを付け、コメントは右側の差分の下に表示されます。その差分の最新のコメントが Claude のもので、まだ返信していなければ、パネルの `c` はそれへの返信になります。返信や編集の対象があるときは、どうするかを尋ねます。最も妥当な選択がデフォルトなので、`RET` で Claude に返信できます。新しいコメントも選べます。Claude のコメントは `▎ #4 Claude: 本文` の形で該当行の下に表示されます。削除行なら左側、追加行なら右側です。`review_navigate` は、ウィンドウを選択せずにその差分と行へ移動します。レビューは diff バッファと同じようにファイルの変更に追従し、現在の差分、左右の表示位置、コメントを保ちます。

| キー | 動作 |
|---|---|
| `c` | ウィンドウではポイントのある行にコメント。`?` で開いたパネルでは現在の差分にコメントし、Claude の最新のコメントがあればそれに返信。もう一度押すと自分のコメントを編集 |
| `{` / `}` | 前 / 次のコメントへ移動 |
| `a` | Claude のコメントの表示・非表示を切り替え |
| `l` | コメントへジャンプ |
| `x` | ポイントのある行のコメントを、なければ現在の差分のコメントを削除（`C-u x` か、どの差分の外でも、すべてのコメントから選ぶ）。diff バッファでは `d` |
| `u` / `d` | 返答の欄を前 / 先へスクロール |
| `RET` | ファイルを専用のフレームに開く。ウィンドウではポイントのある行、`?` で開いたパネルでは現在の差分の位置 |
| `v` / `V` | 両方のウィンドウをスクロール |
| `n` / `p` / `j` | 次・前の差分（ウィンドウではポイントから）、または番号を指定した差分へ。フィルタで隠したファイルは飛ばす |
| `s` | ファイルの一覧の表示・非表示（[ファイルを一覧し絞り込む](#ファイルを一覧し絞り込む)を参照） |
| `/` | フィルタに合うファイルだけを残す |
| `T` / `t` / `M` | Claude に案内を頼む、その次の箇所を頼む、メッセージを送る（[レビューから Claude と話す](#レビューから-claude-と話す)を参照） |
| `y` | Claude が待っている要求に答える（返答の欄に表示） |
| `\|` | 左右の差分を上下に並べる / 左右に並べる。返答の欄も一緒に移る |
| `!` | ファイルを読み直す |
| `C-c C-c` | コメントをプロンプトとして送信（`C-u C-c C-c` で送信前に編集） |
| `C-c C-k` | レビューとコメントを破棄 |
| `q` | レビューを終了 |
| `?` | すべてのキーを載せたコントロールパネルを表示（もう一度押すと隠す） |

コメントは diff バッファと同じく、行か差分全体に付けます。ファイル名と行番号を含み、セッションに送るプロンプトも同じ形式です。コメントを送信するか、`C-c C-k` か `q` を押すと、レビューを開く前のウィンドウ構成に戻ります。ここに `g` コマンドはなく、`!` でレビューを読み直します。

## レビュー表示時のウィンドウ配置

レビューが画面をどれだけ使うかは、次の 2 つの変数で決まります。

| 変数 | 説明 |
|---|---|
| `ecc-window-hide-on-review` | `'project` でこのプロジェクトのセッションを、`'all` で全セッションを隠す。`nil` ではどれも隠さない |
| `ecc-window-review-focus` | `'review` でレビューにフォーカス、`'session` でポイントをトランスクリプトに残す、`nil` でフォーカスを変えない |

隠したウィンドウは保存されません。`C-c c V`（`ecc-space-reset-windows`）でタブ全体を配置し直し、`C-c c v` でセッションを 1 つずつ戻せます。そのほかの設定は[設定リファレンス](/emacs-claude-code/ja/reference/configuration/)を参照してください。
