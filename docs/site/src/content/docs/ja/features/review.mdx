変更を 1 つの diff で確認し、直してほしいハンクにコメントを付け、すべてのコメントを 1 つのプロンプトで送ります。同じバッファで、セッションが変えた内容、変更された作業ツリー、適用前の 1 つの提案をレビューできます。

`D` と `G` は同じレビューで、**比較の基準だけが違います**。

- `D` — **セッションを開始した時点**との差分。セッション中にコミットした変更もそのまま表示されます。
- `G` — **直前のコミット（`HEAD`）** との差分。未コミットの変更だけが対象です。

どちらも、ファイルがどう変更されたかは問いません。編集、シェルコマンド、スクリプトのどれによる変更も同じように表示されます。

## セッション全体の変更をレビューする

Transient メニューで `D` を押すか、`C-c c D` と入力するか、`M-x ecc-review` を実行します。プレフィクス引数を付ける（`C-u D`）と、対象のファイルを尋ねられます。

<Video name="review" label="セッション全体の変更を1つの diff として表示: ハンクにコメントを付け、送信前にプロンプト形式で確認している様子" />

セッション開始時に、ecc はその時点の作業ツリーの内容を記録します。使い捨てのインデックスを通して Git のツリーオブジェクトを書き出すだけなので、スタッシュは作られず、本来のインデックスにもファイルにも触れません。レビューでは、現在のツリーをこのベースラインと比較します。そのため、セッション開始前から進めていた作業は含まれません。また、CLI が編集ツール、シェルコマンド、スクリプトのどれで変更しても表示されます。

基準はコミットではなく「時点」なので、セッション中にコミットした変更も表示されます（`G` では見えなくなります）。セッションを再開しても、ベースラインは変わりません。

基準は時間であって作成者ではないので、同じディレクトリで別のセッションが動いていれば、その変更もここに現れます（Git の worktree を分ければ混ざりません）。`ecc-review-max-bytes`（デフォルトは 200,000）を超えるファイルは、内容ではなくファイル名だけが表示されます。パッケージマネージャーの書き直したロックファイルは、たいていこれに当たります。

Git リポジトリの外では比較するツリーがないため、セッションが最初に変更する前の内容として CLI が報告したものと比較します。以前の挙動が残っているのはここだけです。

| キー | 動作 |
|---|---|
| `c` | ポイント位置のハンクにコメント（再度押すと編集） |
| `l` | コメントを付けた箇所へジャンプ |
| `d` | このハンクのコメントを削除 |
| `e` | 提案内容を編集（単一提案のレビュー時） |
| `C-c C-c` | コメントをプロンプトとして送信（`C-u C-c C-c` で送信前に編集） |
| `C-c C-k` | レビューとコメントを破棄 |
| `g` | diff を読み直す |
| `q` | バッファを隠す |

バッファは読み取り専用の `diff-mode` なので、`n`、`p`、`RET` でハンク間を移動したり、ソースへジャンプしたりできます。コメントを付けたハンクはヘッダーが太字になり、その下にコメントが、ヘッダーラインに件数が表示されます。

`C-c C-c` を押すと、コメントが 1 つのプロンプトにまとまって送信され、レビューが閉じます。コメントがそのままプロンプトになるので、ふつう書き足すことはありません。`C-u C-c C-c` では、送る前に専用のバッファで開きます:

````
## hello.py  L1-L6
```diff
 def greet(name):
     """Say hi."""
-    return "hi " + name
+    return "hello " + name
```
Comment: the docstring still says hi
````

そこでは `C-c C-c` でプロンプトをそのまま送信でき、`C-c C-k` で diff に戻れます。

## 作業ツリーをレビューする

`ecc-review` がセッション開始の時点から比べるのに対し、`ecc-review-worktree` は直前のコミットから比べます。メニューで `G` を押すか、`C-c c G` を入力するか、`M-x ecc-review-worktree` を実行します。

プロジェクトのリポジトリ全体を `HEAD` と比較します。ステージ済みかどうかにかかわらず未コミットの変更をすべて表示し、未追跡のファイルも含めます。`.gitignore` で除外したファイルは含みません。バイナリファイルと `ecc-review-max-bytes` を超えるファイルは、内容ではなくファイル名だけを表示します。コミットがまだないリポジトリでは空のツリーと比較するので、プロジェクトで最初に書いたコードもコミット前にレビューできます。`C-u G` では比較対象を尋ねられます。リビジョン、`main...HEAD` のような範囲、または未ステージの変更だけを見るなら空のまま入力します。

対象のプロジェクトはカレントバッファで決まり、コメントはそのプロジェクトのセッションに送られます。セッションがなければ、ecc が開始するかを尋ねます。たいていはここからセッションを始めることになります。コメントの付け方と送り方は上と同じで、2 つのレビューは別々のバッファを使います。

コメントには対象のハンク全体が入るので、ハンクは変更そのものの大きさに抑えています。広げるには `(setq ecc-review-context-lines 3)` を設定します。この値は ecc が git を実行するときに `-U` として渡すので、`git config` を読み書きすることはありません。提案のレビューは、この設定にかかわらず `ecc-review-proposal-context-lines` で前後 3 行を表示します。

## ediff でレビューを開く

`ecc-review-style` で、`D` と `G` が変更をどう表示するかを決めます。デフォルトの `'diff` では、ここまでに説明した 1 つの `diff-mode` バッファを使います。`'ediff` に設定すると、ファイルを左右に並べて表示します:

```elisp
(setq ecc-review-style 'ediff)
```

レビューするファイルは、ファイルごとではなく、すべて 1 つの ediff セッションで開きます。変更前の内容は左のバッファに、変更後の内容は右のバッファに連結されます。各ファイルは `═══ path ═══` のような区切り行で区切られ、ファイル同士がつながらないよう直前に空行が入ります。すべての変更が 1 つのセッションにあるので、`n` と `p` でレビュー全体の差分を順に移動でき、ファイルの境目もそのまま越えます。git がバイナリとみなすファイルと `ecc-review-max-bytes` を超えるファイルは、区切り行だけになり、差分は含まれません。区切り行は `═══ photo.png (binary, not shown) ═══` のようになります。

2 つのバッファは左右に並んで表示されます。`ecc` は `ediff-split-window-function` をレビューのコントロールバッファでだけ設定するので、ほかの ediff セッションは自分で設定したウィンドウ配置のままです。

どちらのバッファも読み取り専用なので、ediff のコピーコマンド `a` と `b` はここでは何もしません。変更を確認し、コメントを付けて送信します。コメントから生成されたプロンプトをもとに、Claude がディスク上のファイルを更新します。

| キー | 動作 |
|---|---|
| `c` | 現在の差分にコメント（再度押すと編集） |
| `l` | コメントを付けた箇所へジャンプ |
| `d` | 現在の差分のコメントを削除 |
| `C-c C-c` | コメントをプロンプトとして送信（`C-u C-c C-c` で送信前に編集） |
| `C-c C-k` | レビューとコメントを破棄 |
| `q` | レビューを終了 |
| `?` | ヘルプ全体を表示（再度押すと非表示） |

コメントは diff バッファと同じように扱われます。ファイル名と行番号が入り、セッションに送るプロンプトも同じです。コメントを送っても、`C-c C-k` や `q` を押しても、レビューを開く前のウィンドウ構成に戻ります。ここには `g` がありません。レビューを更新するには、一度終了して開き直してください。

## 適用前の提案をレビューする

<Video name="proposal" label="提案されたファイル変更内容を専用バッファで直接修正し、修正後の内容で許可する様子" />

トランスクリプトでツールの権限リクエストが待機中のとき、リクエストのノードで `c` を押すとその変更をレビューでき、`e` を押すと提案された内容が開きます（[プロンプトとトランスクリプト](/emacs-claude-code/ja/features/prompt/#回答待ちリクエストノード上での操作)を参照）。

ここでのコメントは **拒否の理由** として送られます。書き込んだあとで直させるのではなく、Claude に提案をやり直させられます。

`e` を押すと対象ファイルのメジャーモードで提案が開きます。`C-c C-c` は Claude のテキストの代わりに編集後のテキストで変更を許可し、どこを変えたかの diff を送ります。`C-c C-k` はリクエストを保留のままにします。

## プランモード

プランモードを抜けると、プランがリクエストとして届きます。ecc はそれを、セッションの隣の編集できるバッファで開きます。

<Video name="plan" label="プランが専用バッファで開き、行にコメントを付け、権限モードを選んで、コメント付きでプランを差し戻す様子" />

フィードバックの方法は 3 通りあります。行コメント（`C-c C-a`、削除は `C-c C-r`）、行内の `@claude: …` マーカー、計画自体の編集（`C-c C-d` で差分を表示）です。

フィードバックがあれば、`C-c C-c` はそれを添えて計画を差し戻し、作り直しを求めます。フィードバックがなければ計画を承認し、権限モードを決めます。`C-c C-p` で選べ、選ばなければ `ecc-plan-default-mode`（`"acceptEdits"`）を使います。

| キー | 動作 |
|---|---|
| `C-c C-c` | 承認、フィードバックがあればそれを送信 |
| `C-c C-k` | 理由を添えて却下（フィードバックも含める） |
| `C-c C-a` / `C-c C-r` | 現在行にコメントを追加 / 削除 |
| `C-c C-d` | 提案された計画に対する編集差分を表示 |
| `C-c C-p` | 承認するときの権限モードを選択 |
| `C-c C-n` | 前回の計画から変更された次の行へ |

再提案されたプランでは、変更された行がマージンにマークされ、ヘッダーラインに `+N −N` が表示されます。

## 変更ファイル一覧 (Files セクション)

<Video name="files" label="トランスクリプト末尾の変更ファイル一覧: ファイルを展開して差分を確認し、単体レビューへ進む様子" />

トランスクリプトの末尾には、セッション中に触れたファイルが並びます（パス、`R×n` 読み込み／`E×n` 編集／`W×n` 書き込みの回数、`+n −n` の変更行数）。`TAB` でそのファイルの累積 diff を展開し、`RET` でファイルを開き、`d` でそのファイルだけをレビューします。

トランスクリプトで `f`（メニューでは `F`）を押すとこのセクションへジャンプします。`ecc-render-summary-position` を `'top` に設定すると、末尾ではなく先頭に配置されます。

## タイムライン

トランスクリプトで `T` を押すと、ターンがプロンプトで一覧され、選んだターンへジャンプします。`C-c C-n` と `C-c C-p` でターンを1つずつ移動します。

## レビュー表示時のウィンドウ配置

レビューが画面をどれだけ使うかは、次の 2 つの変数で決めます:

| 変数 | 説明 |
|---|---|
| `ecc-window-hide-on-review` | `'project` でこのプロジェクトのセッションを非表示、`'all` で全セッションを非表示、`nil` でそのまま維持 |
| `ecc-window-review-focus` | `'review` でレビューバッファにフォーカス、`'session` でトランスクリプトにポイントを維持、`nil` で元のフォーカスのまま |

隠したウィンドウは保存されません。`C-c c V`（`ecc-space-reset-windows`）でタブ全体を配置し直せます。セッションを 1 つずつ戻すなら `C-c c v` です。そのほかの設定は[設定リファレンス](/emacs-claude-code/ja/reference/configuration/)にあります。
