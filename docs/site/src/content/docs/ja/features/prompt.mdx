セッションバッファには、上からトランスクリプト、区切り線の下にプロンプトの入力領域、いちばん下にフッターが並びます。トランスクリプトは読み取り専用のテキストで、テキストプロパティで専用のローカルキーマップが付いているため、1 文字のキーでコマンドが動きます。プロンプト領域にはこのプロパティがなく、メジャーモードのキーマップ（`RET`、`TAB`、移動キー、`C-c C-` プレフィクスだけをバインド）に従うので、キーを押せば普段どおり文字が入ります。

## プロンプト入力領域

### 入力と送信

| キー | 動作 |
|---|---|
| `RET` | 改行を挿入（`ecc-chat-return-sends` が有効な場合は送信） |
| `S-RET`, `C-j` | 改行を挿入 |
| `C-c C-c` | プロンプトを送信 |
| `C-c C-k` | プロンプト領域をクリア |
| `C-k` | 表示行をキル（プロンプト領域の外には出ない） |
| `C-a` / `C-e` | 表示行の先頭 / 末尾へ移動 |
| `TAB` | スラッシュコマンドまたは `@` 参照の補完 |
| `/` | スラッシュを挿入（空のプロンプトで押した場合はコマンド候補を表示） |

### 履歴と提案プロンプト

| キー | 動作 |
|---|---|
| `M-p` / `M-n`, `C-<up>` / `C-<down>` | 履歴から前 / 次のプロンプトを呼び出し |
| `C-c C-r` | 履歴から選んでカーソル位置に挿入 |
| `C-c C-s` | CLI からの提案プロンプトを採用 |

プロンプトの履歴はすべてのセッションで共有されます。あるセッションで入力したプロンプトは、すぐに別のセッションでも使えます。

`M-p` はプロンプト領域全体を置き換えるので、古い履歴まで遡るのは大変です。`C-c C-r`（`ecc-prompt-history-insert`）は履歴を新しい順に 1 件 1 行の補完候補として表示し、選んだプロンプトの全文をカーソル位置に挿入します。書きかけの文章はそのまま残ります。

1〜2 ターンのあと、CLI が次のプロンプトを提案することがあります。提案は空のプロンプト領域にゴーストテキストとして表示され、`C-c C-s` で編集できる下書きとして取り込めます。

<Video name="suggestion" label="空のプロンプト領域に表示された提案を C-c C-s で採用して送信する様子" />

提案が表示されるのは、`ecc-prompt-suggestions-enabled` が non-nil のとき（CLI に `--prompt-suggestions` を渡します）だけです。提案に対応していないモデルもあります。

### プレフィクスキーバインド (C-c C-)

| キー | 動作 |
|---|---|
| `C-c C-q` | キューに入っているプロンプトを表示 |
| `C-c C-z` | 実行中のターンを中断（`C-c C-g` はあえて割り当てていない。ほかの場所と同じくプレフィクスの取り消しになる） |
| `C-c C-x` | エディタコンテキストの自動添付を切り替え |
| `C-c C-i` | 画像を挿入 |
| `C-c C-a` / `C-c C-d` | 待機中リクエストを許可 / 拒否 |
| `C-c C-n` / `C-c C-p` | 次 / 前のターンへ移動 |
| `C-c C-b` | `/btw` サイドクエリを表示 |
| `C-c C-t` | このウィンドウで別のセッションを表示 |
| `C-c C-e` | 会話を Markdown としてエクスポート |
| `S-TAB` | 権限モードを切り替え |
| `C-c ?` | Transient メニューを開く |

`C-c C-a` と `C-c C-d` を使えば、プロンプト領域を離れずに応答できます。ポイント位置にリクエストがあればそれに、なければこのセッションで最も古い待機中のリクエストに、それもなければ全セッションで最も古いリクエストに応答します。

### `@` 参照によるコンテキスト挿入

<Video name="at-cursor" label="@cursor を含むプロンプトの例: 参照がファイル名と行番号に展開され、コード内容が添付される様子" />

プロンプトの `@` で、Claude に読ませるコンテキストを指定します。`TAB` で、次の表の参照とプロジェクト内のファイルを補完できます。

| 参照 | 説明 |
|---|---|
| `@region` | アクティブなリージョン（引用コードブロックとして添付） |
| `@cursor` | ポイントのある行と、その前後の行 |
| `@diagnostics` | カレントバッファの診断情報（Flymake / Flycheck） |
| `@path:10-40` | 指定したファイルの特定の行（例: 10〜40 行目） |
| `@path` | CLI が直接解決するファイルパス参照 |

表の上から4 つの参照は、送信前に Emacs が展開します。プロンプト中の参照は短いラベルに置き換わり、参照先の内容は区切り線の下に引用ブロックとして追加されます（同じ参照が複数あってもブロックは1 つです）。エコーエリアに何を添付したかが表示され、リージョンを選ばずに `@region` を使うと警告が出ます。

リージョン、カーソル位置、診断は、セッションバッファへ切り替える前に編集していたバッファから取得します。

### スラッシュコマンド

![セッション上に開いたスラッシュコマンド候補と、CLI から提供された各説明文](../../../../assets/slash.png)

プロンプトの先頭で `/` を入力すると、コマンドの一覧が表示されます。プロンプトのどこでも、`TAB` でスラッシュコマンドを補完できます。各コマンドには CLI が返した説明が付きます。

`/model`、`/effort`、`/permissions`、`/config`、`/btw` は、まず引数を尋ねます。引数なしで送ると、CLI が使い方の説明を返すためです。ターミナル専用のコマンドは補完候補に出ませんが、コマンド名を最後まで入力すれば実行できます。

CLI の一覧にないコマンドのうち、`/btw`、`/hooks`、`/plugins`、`/login`、`/logout`、`/auth-status`、`/resume` は Emacs が処理し、モデルには届きません。

### `/btw` によるサイドクエリ

`/btw <質問内容>` を送ると、メインの会話とは別に質問できます。Emacs がこのコマンドを横取りし、軽量な CLI を別に起動します。この CLI はここまでの文脈を共有しますが、ツールは使えません。質問も回答も、トランスクリプトとセッションの記録には残りません。

<Video name="btw" label="トランスクリプトの回答生成が続く横で、サイドクエリが並行して回答される様子" />

進行中のターンは中断されません。トランスクリプトのストリーミングが続く間に、`/btw` の回答は別の画面に届きます。`C-c C-b` でセッションのサイドクエリを一覧でき、`a` で別の質問、`c` で回答のコピー、`k` で実行中の問い合わせのキャンセル、`x` で一覧の消去、`q` でバッファを閉じます。回答をフローティングポップアップ（posframe）に出すか通常のウィンドウに出すかは、`ecc-btw-display` で選びます。

`/btw` は1 回きりの問い合わせです。続けて質問しても、含まれるのは直近の数往復だけです（`ecc-btw-history-limit`）。

### `/resume` で別の会話に切り替える

`/resume` は、このプロジェクトで記録されたどの会話を続けるかを尋ね、現在のウィンドウをその会話に切り替えます。ウィンドウ、タブ、バッファ、セッション名はそのままで、切り替わるのは中身の会話だけです。これはターミナルクライアントの `/resume` と同じ動作です。CLI はヘッドレスのクライアントにこのコマンドを提供していないので、ここでの `/resume` は ecc が Emacs で実装したものです。

Emacs はまず実行中の CLI プロセスを止めます（実行中のターンは中断し、終わるのを待ちます）。1 つのセッション ID で2 つのプロセスが動くと、知らないうちに記録が分岐するためです。会話にターンやキューに入ったプロンプトがあれば、離れる前に確認を求めます。離れた会話は残り、`ecc-history-open` でまた読めます。

`/resume <session-id>` は、尋ねずにその ID の記録を再開します。Space では、何も動いていないプロジェクトを開くと新しいセッションが始まり、`/resume` で前の会話に戻れます。

### ターン実行中のプロンプト送信

Claude の作業中に送ったプロンプトは、ターンを中断せずキューに入ります。エコーエリアには、キューの何番目かが表示されます。キューは `C-c C-q` で確認できます。Remote Control から始まったターンも同じようにキューに入り、通知でそれとわかるようになっています。

### 画像とエディタコンテキスト

貼り付け、バッファへのドラッグ、`C-c C-i` で挿入した画像は `ecc-image-dir` の下に保存され、ファイルパスとして CLI に渡されます。セッション終了時にそのセッションの画像を削除するかは、`ecc-image-cleanup` で決めます。

<Video name="image" label="画像をプロンプトにパスとして挿入し、回答で画像が解説される様子" />

画像は送信されるだけでなく、トランスクリプトにも表示されます。プロンプトに添付した画像は、指示を出したプロンプト帯の下に表示されます。Claude が返した画像は、それを生成した呼び出しの下に表示されます。これには、メッセージ内の `image` ブロック、`.png` の `Read` の結果、MCP ツールのスクリーンショットが含まれます。Base64 データがバッファに入ることはありません。ペイロードはセッションの画像ディレクトリに書き出され、トランスクリプトはそのパスのみを保持します。

`PATH` 上に `ffmpeg` があれば、動画の先頭フレームが表示され、`RET` を押すと外部プレイヤーで動画が開きます。`ffmpeg` が利用できない場合は、ファイル名を示す行だけが表示されます。フレームの取り出しはサブプロセスで実行され、Emacs を止めません。そのため、フレームの準備ができるまではファイル名の行が表示されます。

GIF は表示されるとすぐにアニメーションを開始し、画面内にある限りループします。GIF 上で `I` を押すと停止または再開します。`I` が制御するのはアニメーションのみです。`RET` はファイルを開きます（静止画は `image-mode`、動画は外部プレイヤー）。`ecc-image-inline`（メニューの `I`）は画像表示をオフにし、ファイル名を示す行だけを残します。表示される画像は高さが制限され、幅は `ecc-chat-text-width` に従います。

`C-c C-x` は、そのバッファのエディタコンテキストのオン・オフを切り替えます。オンのときは、現在のファイル名と行番号が毎回のプロンプトに自動で付きます。

<Video name="context" label="C-c C-x でコンテキストを有効にし、次のプロンプトにファイル名と行番号が付加される様子" />

### フッター表示

プロンプト入力領域の下には区切り線があり、左に現在の権限モード、右に使用中のモデルが表示されます。`S-TAB` で `default`、`acceptEdits`、`plan`、`auto` を順に切り替えます。うっかりオンにしないよう、`bypassPermissions` はこの順番に入っていません。選ぶには `ecc-set-permission-mode` を使います。プロンプトが空のときに出るプレースホルダーは、バッファのテキストではなくオーバーレイです。

## トランスクリプト

<Video name="fold" label="トランスクリプトの折りたたみ: 全体を畳み、階層ごとに開き、TAB で特定ノードを開閉する様子" />

トランスクリプトは普通の読み取り専用のテキストなので、`isearch`、`occur`、narrowing、`M-w` が Emacs のほかの場所と同じように使えます。

### 折りたたみ (Folding)

| キー | 動作 |
|---|---|
| `TAB` | ポイント位置のノードを開閉 |
| `1`–`4` | 指定した深さまでツリーを展開 |
| `+` / `-` | すべてのノードを展開 / 折りたたむ |

### ナビゲーション

| キー | 動作 |
|---|---|
| `n` / `p` | 次 / 前の見出しへ移動 |
| `M-n` / `M-p` | 同じ深さの次 / 前のノードへ移動 |
| `^` | 親の見出しへ移動 |
| `]` / `[` | 次 / 前のブロックへ移動 |
| `T` | プロンプト一覧からターンを選んでジャンプ |
| `F` / `P` | 変更ファイル一覧セクション / プランセクションへ移動 |
| `SPC` / `DEL` | 下 / 上へスクロール |
| `v` / `i` | プロンプト入力領域へ移動 |

### ポイント位置の項目に対する操作

| キー | 動作 |
|---|---|
| `RET` | ポイント位置の項目を開く: リンク、diff の行やパスが指すソース（[ソースを開く](#ソースを開く)を参照）、サブエージェントのトランスクリプト、ツールの結果全文 |
| `o` | ポイント位置のノードの詳細（入力・diff・結果の全文）を表示 |
| `mouse-1` / `mouse-2` | クリックしたリンク、diff の行、ファイルの見出しを開く |
| `w` | ポイント位置のコードブロック（または回答全体）をコピー |
| `I` | ポイント位置の GIF アニメーションを停止・再開 |
| `a` | 待機中リクエストを許可 |
| `d` | ポイント位置のリクエストを拒否（リクエスト以外の場所では diff を表示） |
| `g` | トランスクリプトを再描画 |
| `L` | 生のプロトコルログを表示 |
| `t` / `R` | ターミナルクライアントへ引き渡し / セッション再開 |
| `C-c C-k` | プロンプト領域をクリア（プロンプト側と同じ。バッファ内では1 つのキーに1 つの意味） |
| `S-TAB` | 権限モードを切り替え |
| `q` | バッファを後ろに回す（bury-buffer） |
| `?` | Transient メニューを開く |

### ソースを開く

トランスクリプトのコードの上で `RET` を押すかクリックすると、セッションの隣にファイルが開きます。ポイントはその行に移り、行が一瞬光ります。

| ポイントの位置 | 開く場所 |
|---|---|
| Edit、MultiEdit、Write、NotebookEdit、Bash の diff の行 | その行（削除された行は、削除された位置） |
| Bash の diff の上にある `Updated`・`Created`・`Deleted` の行 | そのファイルで最初に変更した行 |
| ファイルを扱うツール呼び出しの見出し | Read は `offset` の行、編集は最初に変更した行 |
| Files セクションや許可リクエストの diff の行 | その行 |
| Claude の返答中のパス（`foo.el:12`、`a/b.el`、`x.el#L3`。バッククォート内も対象） | セッションのディレクトリから見たファイルの、指定された行 |

diff の行番号は、その変更を加えた直後のファイルでの行です。セッションがあとから同じファイルを変更した分も補正するので、その行が今ある位置で開きます。返答中のパスは、開くときにはじめて存在を確認し、ファイルがなければエラーになります。コードブロック内のパスはリンクになりません。パスのリンクを無効にするには、変数 `ecc-markdown-linkify-paths` を `setq` で nil にします。

動画や音声のファイル（`clip.mp4`、`take.mp3`）は Emacs では開きません。トランスクリプトに描いた動画と同じく、`RET` でマシンのプレイヤーを起動して再生し、行番号は無視します。

Bash が変更したファイルは、CLI が報告したときに限り、その出力の下に表示されます。デフォルトでは表示されません。ecc は CLI を `default` モードで起動し、Claude Code CLI 2.1.286 はこのモードでは報告しないためです。報告するのは `auto` と `bypassPermissions` モードだけで、それもモデルによって変わる CLI の実験フラグが有効な場合に限られます。どのモードでも表示するには、`~/.claude/settings.json` に `"bashEditDiffEnabled": true` を追加するか、`--settings` で渡します。プロジェクトの `.claude/settings.json` に書いても有効になりません。これは Claude Code の設定なので、ecc が代わりに設定することはありません。いずれの場合も、ファイルが git リポジトリの中にある必要があります。

Bash のようにファイルを指さない見出しでは、`RET` でツールの結果全文を表示します。`o` はどのノードでも全文を表示します。

### 回答待ちリクエストノード上での操作

ユーザーの入力を待っているノードでは、ポイントがその中にある間、専用のローカルキーマップが有効になります:

<Video name="permission" label="ファイルの書き込み権限リクエストに対し、a で許可してターンが完了する様子" />

| キー | 動作 |
|---|---|
| `RET` | 提案の中身を確認（質問の場合は回答用バッファを開く） |
| `a` / `d` | 1 回のみ許可 / 拒否 |
| `A` | このセッションでは、このツールを常に許可 |
| `u` | 現在のターンが完了するまで全リクエストを許可 |
| `r` | 一致するルールで許可（パターンをプロジェクト設定に保存） |
| `c` / `e` | 提案にコメント / 編集してから許可 |

これらのキーはトランスクリプトのほかの場所では使っていないので、ほかのコマンドを隠しません。効くのは、ポイントがリクエストのノードの中にある間だけです。`c` と `e` の詳細は[レビューとプランモード](/emacs-claude-code/ja/features/review/)を参照してください。

質問には、`RET` で開く専用のバッファで答えます。`1`–`9` で選択肢を選び、`SPC` で複数選択の項目をオン・オフし、`o` で自由に回答を入力し、`C-c C-c` で送信します。

<Video name="question" label="2問ある質問: 1問目で選択肢を1つ選び、2問目で2つをオンにして回答を送信する様子" />

### 変更ファイル一覧 (Files セクション)

`RET` で選んだファイルを開き（diff の行の上ならその行へ）、`d` でその変更を diff-mode で確認します。`TAB` で開閉し、`SPC` でスクロールします。

セッションバッファの外から使えるコマンドは、すべて [Transient メニュー](/emacs-claude-code/ja/features/menu/)のページにあります。
