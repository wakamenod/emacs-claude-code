変更を 1 つの diff として確認し、手を入れたいハンクにコメントを付け、すべてのコメントを 1 つのプロンプトとして送信できます。同じバッファで、セッションによる変更内容、変更された作業ツリー、適用前の個別提案のいずれもレビューできます。

`D` と `G` は同じレビューで、**比較の基準だけが違います**。

- `D` — **セッションを開始した時点**との差分。セッション中にコミットした変更もそのまま表示されます。
- `G` — **直前のコミット（`HEAD`）** との差分。未コミットの変更だけが対象です。

どちらも変更の手段は問いません。編集・シェルコマンド・スクリプトのいずれで行われた変更も同じように表示されます。

## セッション全体の変更をレビューする

Transient メニューで `D` を押すか、`C-c c D` を入力するか、`M-x ecc-review` を実行します。プレフィクス引数（`C-u D`）で対象ファイルを指定できます。

![セッション全体の変更を1つの diff として表示: ハンクにコメントを付け、送信前にプロンプト形式で確認している様子](../../../../assets/review.gif)

セッション開始時に、ecc はその時点の作業ツリーの内容を記録します。使い捨てのインデックス経由で Git のツリーオブジェクトを書き出すだけなので、スタッシュは作られず、実際のインデックスにもファイルにも影響しません。レビューは現在のツリーをこのベースラインと比較します。したがってセッション開始前から進めていた自分の作業は対象外になり、CLI が編集ツール・シェルコマンド・スクリプトのどれを使った変更であっても等しく表示されます。

基準がコミットではなく「時点」であるため、セッション中にコミットした変更も引き続き表示されます（`G` では見えなくなります）。セッションを再開してもベースラインはそのまま保持されます。

注意点が 2 つあります。基準は時間であって作成者ではないため、同じディレクトリで別のセッションが動いていればその変更もここに現れます（Git の worktree を分ければ混ざりません）。また `ecc-review-max-bytes`（既定 200,000）を超えるファイルは、内容ではなくファイル名のみ表示されます。パッケージマネージャーが書き直したロックファイルが典型例です。

Git リポジトリ外では比較対象のツリーが存在しないため、セッションが最初に変更を加える前の状態として CLI が報告した内容と比較されます。従来の挙動が残るのはこの場合だけです。

| キー | 動作 |
|---|---|
| `c` | ポイント位置のハンクにコメント（再度押すと編集） |
| `l` | コメントを付けた箇所へジャンプ |
| `d` | このハンクのコメントを削除 |
| `e` | 提案内容を編集（単一提案のレビュー時） |
| `C-c C-c` | コメントをプロンプトとして送信（`C-u C-c C-c` で送信前に編集） |
| `C-c C-k` | レビューとコメントを破棄 |
| `g` | diff を読み直す |
| `q` | バッファを隠す |

バッファは読み取り専用の `diff-mode` で開くため、`n`、`p`、`RET` でハンク間の移動やソースへのジャンプが可能です。コメントを付けたハンクはヘッダーが太字になり、その下にコメントが、ヘッダーラインに件数が表示されます。

`C-c C-c` を押すと、コメントが 1 つのプロンプトにまとまって送信され、レビューが閉じます。コメント自体がプロンプトなので通常は付け足すことがありませんが、`C-u C-c C-c` なら専用のバッファで先に開きます:

````
## hello.py  L1-L6
```diff
 def greet(name):
     """Say hi."""
-    return "hi " + name
+    return "hello " + name
```
Comment: the docstring still says hi
````

そこでは `C-c C-c` でプロンプトをそのまま送信でき、`C-c C-k` で diff に戻れます。

## 作業ツリーをレビューする

`ecc-review` がセッション開始時点を起点とするのに対し、こちらは直前のコミットを起点とします。メニューで `G` を押すか、`C-c c G` を入力するか、`M-x ecc-review-worktree` を実行します。

プロジェクトのリポジトリ全体を `HEAD` と比較し、ステージの有無にかかわらず未コミットの変更がすべて表示され、未追跡ファイルも含まれます（`.gitignore` の除外対象は含まれません。バイナリファイルや `ecc-review-max-bytes` を超えるファイルは、内容ではなくファイル名のみ表示されます）。まだ 1 つもコミットがないリポジトリでは空のツリーと比較されるため、プロジェクト最初のコードをコミット前にレビューできます。`C-u G` で比較対象（リビジョン、`main...HEAD` などの範囲、または未ステージの変更のみとする空入力）を指定できます。

対象のプロジェクトはカレントバッファに基づいて判定され、コメントはそのプロジェクトのセッションに送られます。セッションが存在しない場合は起動を促されます（通常はこれが起動の起点になります）。コメントの付け方や送信手順は上記と同様で、2 つのレビューには別々のバッファが使われます。

コメントには注釈対象のハンク全体が含まれるため、ハンクは変更箇所のみの最小限のサイズになります。前後の行数を広げたい場合は `(setq ecc-review-context-lines 3)` を設定してください。この値は ecc が実行する git コマンドに `-U` 引数として渡されるため、`git config` の読み書きは行われません。なお、提案のレビューは設定にかかわらず前後 3 行のコンテキストが保持され、`ecc-review-proposal-context-lines` で調整します。

## ediff でレビューを開く

`ecc-review-style` で、`D` と `G` による変更の表示方法を設定します。デフォルトの `'diff` では、前述の単一 `diff-mode` バッファを使います。これを `'ediff` に設定すると、ファイルを左右に並べて表示します:

```elisp
(setq ecc-review-style 'ediff)
```

レビュー対象の全ファイルは、ファイルごとではなく 1 つの ediff セッションにまとめて開きます。変更前の内容は左のバッファに、変更後の内容は右のバッファに連結します。各ファイルは `═══ path ═══` のような区切り行で区切られ、ファイル同士がつながらないよう直前に空行が入ります。すべての変更が 1 つのセッションにまとまっているため、`n` や `p` でファイルをまたぎながら、レビュー全体の差分を順に移動できます。git がバイナリと判定したファイルや、`ecc-review-max-bytes` を超えるファイルは、`═══ photo.png (binary, not shown) ═══` のような区切り行のみを表示し、差分は含みません。

2 つのバッファは左右に並んで表示されます。`ecc` は `ediff-split-window-function` をレビューのコントロールバッファにのみ設定するため、他の ediff セッションでは普段設定しているウィンドウ配置がそのまま維持されます。

両方のバッファは読み取り専用です。そのため、ediff のコピーコマンド（`a` や `b`）は機能しません。差分を読み、コメントを付けて送信するだけで操作は完結します。コメントから生成されたプロンプトをもとに、Claude がディスク上のファイルを更新します。

| キー | 動作 |
|---|---|
| `c` | 現在の差分にコメント（再度押すと編集） |
| `l` | コメントを付けた箇所へジャンプ |
| `d` | この差分のコメントを削除 |
| `C-c C-c` | コメントをプロンプトとして送信（`C-u C-c C-c` で送信前に編集） |
| `C-c C-k` | レビューとコメントを破棄 |
| `q` | レビューを閉じる |
| `?` | ヘルプ全体を表示（もう一度押すと非表示） |

コメントの扱いは diff バッファと同じです。ファイル名とファイル内の行番号を保持し、セッションに送信されるプロンプトも完全に同一です。コメントの送信、`C-c C-k`、`q` のいずれを実行しても、レビューを開く前のウィンドウ構成に戻ります。ここには `g` コマンドがありません。レビューを更新したいときは、一度終了して再度開いてください。

## 適用前の提案をレビューする

![提案されたファイル変更内容を専用バッファで直接修正し、修正後の内容で許可する様子](../../../../assets/proposal.gif)

トランスクリプト上でリクエストが承認待ちのとき、リクエストノードで `c` を押すとその変更をレビューでき、`e` を押すと提案された内容が開きます（詳細は [プロンプトとトランスクリプト](/emacs-claude-code/ja/features/prompt/#回答待ちリクエストノード上での操作) を参照）。

ここでのコメントは **拒否の理由** として送信され、ファイル書き込み後に修正させるのではなく、事前に Claude へ再提案を促せます。

`e` を押すと対象ファイルのメジャーモードで提案が開きます。`C-c C-c` は Claude の提案の代わりに編集後のテキストで変更を許可し、変更箇所の diff を添えて送信します。`C-c C-k` はリクエストを保留のままにします。

## プランモード

プランモードを抜けると計画がリクエストとして送信され、ecc はそれをセッションの横の編集可能なバッファで開きます。

![プランが専用バッファで開き、権限モードを選択して計画を承認する様子](../../../../assets/plan.gif)

フィードバックの方法は 3 通りあります。行コメント（`C-c C-a`、削除は `C-c C-r`）、行内の `@claude: …` マーカー、計画自体の編集（`C-c C-d` で差分を表示）です。

フィードバックがある場合は `C-c C-c` でそれを添えて計画を差し戻し、再提案を求めます。フィードバックがなければ計画を承認し、権限モードの選択を求めます。`C-c C-p` で選択できるほか、指定しない場合は `ecc-plan-default-mode`（既定値: `"acceptEdits"`）が使用されます。

| キー | 動作 |
|---|---|
| `C-c C-c` | 承認、フィードバックがあればそれを送信 |
| `C-c C-k` | 理由を添えて却下（フィードバックも含める） |
| `C-c C-a` / `C-c C-r` | 現在行にコメントを追加 / 削除 |
| `C-c C-d` | 提案された計画に対する編集差分を表示 |
| `C-c C-p` | 承認後の権限モードを選択 |
| `C-c C-n` | 前回の計画から変更された次の行へ |

再提案されたプランでは、変更された行がマージンにマークされ、ヘッダーラインに `+N −N` が表示されます。

## 変更ファイル一覧 (Files セクション)

![トランスクリプト末尾の変更ファイル一覧: ファイルを展開して差分を確認し、単体レビューへ進む様子](../../../../assets/files.gif)

トランスクリプトの末尾には、セッション中に操作されたファイルが一覧表示されます（ファイルパス、`R×n` 読み込み／`E×n` 編集／`W×n` 書き込みの各操作、`+n −n` の変更行数）。`TAB` でそのファイルの累積 diff を展開し、`RET` でファイルを開き、`d` で単体レビューを行えます。

トランスクリプトで `f`（メニューでは `F`）を押すとこのセクションへジャンプします。`ecc-render-summary-position` を `'top` に設定すると、末尾ではなく先頭に配置されます。

## タイムライン

トランスクリプトで `T` を押すと、各ターンがプロンプト一覧で表示され、選んだターンへジャンプします。`C-c C-n` と `C-c C-p` でターンを前後に移動できます。

![タイムライン: 各ターンのプロンプト一覧から目的のやりとりにジャンプする様子](../../../../assets/timeline.png)

## レビュー表示時のウィンドウ配置

レビューには画面スペースが必要です。次の 2 つの変数でウィンドウの表示やフォーカスを制御できます:

| 変数 | 説明 |
|---|---|
| `ecc-window-hide-on-review` | `'project` でこのプロジェクトのセッションを非表示、`'all` で全セッションを非表示、`nil` でそのまま維持 |
| `ecc-window-review-focus` | `'review` でレビューバッファにフォーカス、`'session` でトランスクリプトにポイントを維持、`nil` で元のフォーカスのまま |

何を隠したかは記録されません。`spaces` では `C-c c V`（`ecc-space-reset-windows`）がタブごと並べ直して戻し、`classic` では `M-x ecc-focus-project`、あるいは `C-c c v` で 1 つずつ戻します。その他の設定は [設定リファレンス](/emacs-claude-code/ja/reference/configuration/) をご覧ください。
