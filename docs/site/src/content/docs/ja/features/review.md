変更を 1 つの diff として確認し、手を入れたいハンクにコメントを付け、すべてのコメントを 1 つのプロンプトとして送信できます。同じバッファで、セッションによる変更内容、変更された作業ツリー、適用前の個別提案のいずれもレビューできます。

`D` と `G` は同じレビューで、**比較の基準だけが違います**。

- `D` — **セッションを開始した時点**との差分。セッション中にコミットした変更もそのまま表示されます。
- `G` — **直前のコミット（`HEAD`）** との差分。未コミットの変更だけが対象です。

どちらも変更の手段は問いません。編集・シェルコマンド・スクリプトのいずれで行われた変更も同じように表示されます。

## セッション全体の変更をレビューする

Transient メニューで `D` を押すか、`C-c c D` を入力するか、`M-x ecc-review` を実行します。プレフィクス引数（`C-u D`）で対象ファイルを指定できます。

![セッション全体の変更を1つの diff として表示: ハンクにコメントを付け、送信前にプロンプト形式で確認している様子](../../../../assets/review.gif)

セッション開始時に、ecc はその時点の作業ツリーの内容を記録します。使い捨てのインデックス経由で Git のツリーオブジェクトを書き出すだけなので、スタッシュは作られず、実際のインデックスにもファイルにも影響しません。レビューは現在のツリーをこのベースラインと比較します。したがってセッション開始前から進めていた自分の作業は対象外になり、CLI が編集ツール・シェルコマンド・スクリプトのどれを使った変更であっても等しく表示されます。

基準がコミットではなく「時点」であるため、セッション中にコミットした変更も引き続き表示されます（`G` では見えなくなります）。セッションを再開してもベースラインはそのまま保持されます。

注意点が 2 つあります。基準は時間であって作成者ではないため、同じディレクトリで別のセッションが動いていればその変更もここに現れます（Git の worktree を分ければ混ざりません）。また `ecc-review-max-bytes`（既定 200,000）を超えるファイルは、内容ではなくファイル名のみ表示されます。パッケージマネージャーが書き直したロックファイルが典型例です。

Git リポジトリ外では比較対象のツリーが存在しないため、セッションが最初に変更を加える前の状態として CLI が報告した内容と比較されます。従来の挙動が残るのはこの場合だけです。

| キー | 動作 |
|---|---|
| `c` | ポイント位置の行にコメント。`@@` 行ではハンク全体にコメント（再度押すと編集） |
| `{` / `}` | 前 / 次のコメントへ移動 |
| `a` | Claude のコメントの表示・非表示を切り替え |
| `l` | コメントを付けた箇所へジャンプ |
| `d` | この行のコメントを削除（自分のものも Claude のものも。`C-u d` ですべてのコメントから選ぶ） |
| `e` | 提案内容を編集（単一提案のレビュー時） |
| `C-c C-c` | 自分のコメントをプロンプトとして送信（`C-u C-c C-c` で送信前に編集） |
| `C-c C-k` | レビューとコメントを破棄 |
| `g` | diff を読み直す（[ファイルの変更に追従する](#ファイルの変更に追従する)も参照） |
| `q` | バッファを隠す |

バッファは読み取り専用の `diff-mode` です。`n` と `p` でハンク間を、`N` と `P` でファイル間を移動でき、`RET` でソースへジャンプします。

コメントは、付けた行に属します。削除行（`-`）では変更前の側、追加行（`+`）と文脈行では変更後の側についてのコメントになり、`@@` 行ではハンク全体へのコメントになります。コメントは行の下に `▎ #3 本文` の形で表示されます。そのハンクのヘッダーは太字になり、ヘッダーラインには件数が出ます。コメントにはそれぞれ番号が付き、同じバッファで同じ番号が使われることはありません。

`g` で diff を読み直しても、コメントと読んでいた位置はそのまま残ります。ただし、別のタブにあるレビューのウィンドウは先頭に戻ります。ファイルの上のほうが変わって行がずれても、コメントは前後の行まで同じ内容の行へ付け直されます。追いかけるのは `ecc-review-note-max-shift`（既定 100 行）までです。ハンク全体へのコメントは、`@@` 行で、見つからなければ変更前の側で覆っていた行でハンクを探して付け直されます。変更前の側の行は、上に行が追加されても動きません。行がなくなった場合もコメントは捨てられず、`[outdated]` の印を付けて、そのファイルの最初のハンクの上に表示されます。送信するときは、最後に見えていたハンクと一緒に送られます。

## ファイルの変更に追従する

開いているレビューは、そのセッションのツールが完了したとき、ターンが終わったとき、Emacs でそのリポジトリのファイルを保存したときに diff を読み直します。編集だけでなくシェルコマンドやスクリプトによる変更も、同じリポジトリで動く別のセッションによる変更も対象です。Read や Grep のように読むだけのツールは対象外です。`g` と同じく、コメントと読んでいた位置はそのまま残ります。

読み直すのは 0.5 秒後で、入力中はさらに待ちます。続けて起きた変更はまとめて 1 回で読みます。diff が変わっていなければ、バッファには手を付けません。読み直すのは画面に出ているレビューだけです。見えていないレビューは、次に表示されたときに読み直します。フォーカスを奪うことも、ウィンドウを動かすこともなく、入力中のプロンプトにも触れません。コミットなどで変更がすべてなくなっても、レビューは開いたままで、その旨を表示します。そのレビューで `g` を押すと、これまでどおり表示するものがないと報告します。ディレクトリが消えたなどで diff を読めないときは、ヘッダーラインに理由を表示し、`g` を押すまで読み直しません。単一の提案のレビューは読み直しません。

ediff でのレビューも同じようにファイルの変更に追従します。今いる差分と、左右それぞれが表示している行は保たれます。読めなかったときは `!` で読み直せます。[ediff でレビューを開く](#ediff-でレビューを開く)を参照してください。

この追従を止め、`g` を押したときだけ読み直すには次のようにします。

```elisp
(setq ecc-review-auto-refresh nil)
```

## コメントを送信する

`C-c C-c` を押すと、自分のコメントが 1 つのプロンプトにまとまって送信され、レビューが閉じます。コメント自体がプロンプトなので通常は付け足すことがありませんが、`C-u C-c C-c` なら専用のバッファで先に開きます:

````
## hello.py  L1-L6
```diff
 def greet(name):
     """Say hi."""
-    return "hi " + name
+    return "hello " + name
```
Comment: the docstring still says hi
````

行へのコメントは `## hello.py  L3 (new)` のように行を見出しにして、本文にはハンク全体を載せます。行がなくなったコメントは、見出しの末尾に `(outdated)` が付きます。Claude への返信は、先頭に `In reply to Claude's #4:` と返信先のコメントを引用します。

そこでは `C-c C-c` でプロンプトをそのまま送信でき、`C-c C-k` で diff に戻れます。

## 作業ツリーをレビューする

`ecc-review` がセッション開始時点を起点とするのに対し、こちらは直前のコミットを起点とします。メニューで `G` を押すか、`C-c c G` を入力するか、`M-x ecc-review-worktree` を実行します。

プロジェクトのリポジトリ全体を `HEAD` と比較し、ステージの有無にかかわらず未コミットの変更がすべて表示され、未追跡ファイルも含まれます（`.gitignore` の除外対象は含まれません。バイナリファイルや `ecc-review-max-bytes` を超えるファイルは、内容ではなくファイル名のみ表示されます）。まだ 1 つもコミットがないリポジトリでは空のツリーと比較されるため、プロジェクト最初のコードをコミット前にレビューできます。

`C-u G` では、比較対象を訊いたあとに対象のファイルを訊きます。

- `HEAD~1` のようなリビジョンは、作業ツリーと比較します。未追跡ファイルも含みます。
- `main...HEAD`、`HEAD~1..HEAD`、`HEAD^!` のような範囲は、コミット同士を比較します。未追跡ファイルは含みません。
- 空入力は、インデックスと作業ツリーを比較します。未ステージの変更です。
- `--staged`（または `--cached`）は、`HEAD` とインデックスを比較します。ステージ済みの変更だけです。バッファ名には `staged changes` と付きます。

ファイルは補完でいくつでも選べます。空なら全ファイルが対象です。`g` でも[ファイルの変更への追従](#ファイルの変更に追従する)でも、この選択は保たれます。範囲が作業ツリーを含むかどうかは、文字列を読んで判断するのではなく `git rev-parse` に訊いて決めます。`-` で始まる範囲は拒否するので、git のオプションが紛れ込むことはありません。

対象のプロジェクトはカレントバッファに基づいて判定され、コメントはそのプロジェクトのセッションに送られます。セッションが存在しない場合は起動を促されます（通常はこれが起動の起点になります）。コメントの付け方や送信手順は上記と同様で、2 つのレビューには別々のバッファが使われます。

コメントには注釈対象のハンク全体が含まれるため、ハンクは変更箇所のみの最小限のサイズになります。前後の行数を広げたい場合は `(setq ecc-review-context-lines 3)` を設定してください。この値は ecc が実行する git コマンドに `-U` 引数として渡されるため、`git config` の読み書きは行われません。なお、提案のレビューは設定にかかわらず前後 3 行のコンテキストが保持され、`ecc-review-proposal-context-lines` で調整します。

## Claude のコメント

[Emacs の MCP サーバー](/emacs-claude-code/ja/start/installation/)が有効（`ecc-mcp-enabled`）なら、レビューは双方向になります。Claude がレビューを開いて行にコメントを付け、話題にしている箇所までスクロールできます。「この変更をレビューバッファで説明して」「diff をレビューしてコメントを残して」のように、ふつうの言葉で頼んでください。

Claude のコメントは、専用の face `ecc-review-agent-comment-face` を使って `▎ #4 Claude: 本文` の形で表示されます。Claude のコメントだけがある行で `c` を押すと、そのコメントへの返信になり、下にインデントして表示されます。`a` で Claude のコメントを隠したり戻したりでき、隠している間もヘッダーラインには件数が出ます。`C-c C-c` で送るのは自分のコメントだけです。Claude は自分で書いた内容を知っているからです。

| ツール | Claude ができること |
|---|---|
| `review_open` | セッションの変更、範囲を指定した作業ツリー、またはステージ済みの変更（`staged`）のレビューを開く。一部のファイルだけにもできる（`paths`）。開いていれば読み直す |
| `review_hunks` | ファイルと番号付きのハンクを一覧する。ハンクの本文も付けられる |
| `review_comment` | 行（`side` は `new` か `old`）、ハンク、または別のコメントの下（`reply_to`）にコメントを置く |
| `review_comment_apply` | 複数のコメントを一度に置く。1 件でも不正なら 1 件も置かない |
| `review_navigate` | 行、ハンク、コメント、次・前のコメントまでレビューをスクロールする |
| `review_list_comments` | コメントを読む。ユーザーのコメントにはハンクの本文が付く |
| `review_remove_comment` | コメントを 1 件削除する。対応済みのユーザーのコメントも消せる |
| `review_clear_comments` | Claude のコメントを削除する。ユーザーのコメントは指定したときだけ |

Claude はユーザーのコメントを書いたり書き換えたりできませんが、削除はできます。ツールは呼び出したセッションのレビューにだけ作用するため、2 つのセッションが互いのレビューに触れることはありません。

ツールがキーボードを奪うことはありません。Claude が開いたり動かしたりしたレビューは、選択されないままセッションの横に表示されます。セッションのウィンドウも隠れないので、入力中のプロンプトはそのまま残ります。今いるウィンドウを使うことも、別のタブや Space に切り替えることもありません。表示先は、同じセッションの別のレビューのウィンドウ、空いているウィンドウ、セッションのウィンドウを分割した半分の順で決まります。分割してできたウィンドウは `q` で消えます。レビューバッファ向けの `display-buffer-alist` を設定していれば、今いるウィンドウとタブに触れない範囲でその設定に従います。セッションが画面に出ていないときや、空いているウィンドウがないときは、何も前面に出ません。レビューは、Claude が指した位置でバッファの中で待ちます。

これらのツールはバッファに文字を置いてウィンドウを動かすだけで、ファイルは書きません。そのため Emacs は確認なしで許可し、トランスクリプトには呼び出しごとに `auto-allowed` と記録します。他のツールと同じように確認させたい場合は、`ecc-review-agent-auto-allow` を `nil` にしてください。

これらのツールは、ediff で開いているレビューにも使えます。ediff ではハンクは ediff の差分 1 つに当たり、`review_hunks` は差分の番号と左右それぞれの行範囲を返します。ediff はフレームとキーボードを奪うため、Claude が ediff を起動することはありません。ediff のレビューが開いていれば `review_open` はそれを読み直し、開いていなければ `ecc-review-style` が `'ediff` でも diff バッファを開きます。

## ediff でレビューを開く

`ecc-review-style` で、`D` と `G` による変更の表示方法を設定します。デフォルトの `'diff` では、前述の単一 `diff-mode` バッファを使います。`'ediff` に設定すると、ファイルを左右に並べて表示します:

```elisp
(setq ecc-review-style 'ediff)
```

レビュー対象の全ファイルは、ファイルごとではなく 1 つの ediff セッションにまとめて開きます。変更前の内容は左のバッファに、変更後の内容は右のバッファに連結されます。各ファイルは `═══ path ═══` のような区切り行で区切られ、ファイル同士がつながらないよう直前に空行が入ります。すべての変更が 1 つのセッションにまとまっているため、`n` や `p` で次のファイルへと直接またぎながら、レビュー全体の差分を順に移動できます。git がバイナリと判定したファイルや、`ecc-review-max-bytes` を超えるファイルは、`═══ photo.png (binary, not shown) ═══` のような区切り行のみが表示され、差分は含まれません。

2 つのバッファは左右に並んで表示されます。`ecc` は `ediff-split-window-function` をレビューのコントロールバッファにのみ設定するため、他の ediff セッションでは設定済みのウィンドウ配置がそのまま維持されます。

両方のバッファは読み取り専用のため、ediff のコピーコマンド `b` は機能しません。`a` は代わりに Claude のコメントの表示・非表示を切り替えます。変更を確認し、コメントを付けて送信します。コメントから生成されたプロンプトをもとに、Claude がディスク上のファイルを更新します。

あなたのコメントは現在の差分全体へのもので、右側の差分の下に表示されます。その差分の最新のコメントが Claude のもので、まだ返信していなければ、`c` はそれへの返信になります。返信や編集の対象があるときは、どうするかを尋ねます。既定は最も妥当な選択なので、`RET` で Claude に返信できます。新しいコメントも選べます。Claude のコメントは該当行の下に `▎ #4 Claude: 本文` の形で表示されます。削除行なら左側、追加行なら右側です。`review_navigate` はウィンドウを選択せずに、その差分と行へ移動します。レビューは diff バッファと同じようにファイルの変更に追従し、現在の差分、左右の表示位置、コメントを保ちます。

| キー | 動作 |
|---|---|
| `c` | 現在の差分にコメント（再度押すと編集）。Claude の最新のコメントがあればそれへの返信 |
| `{` / `}` | 前・次のコメントへ |
| `a` | Claude のコメントの表示・非表示 |
| `l` | コメントを付けた箇所へジャンプ |
| `d` | 現在の差分のコメントを削除（`C-u d` か差分の外では、すべてのコメントから選ぶ） |
| `!` | ファイルを読み直す |
| `C-c C-c` | コメントをプロンプトとして送信（`C-u C-c C-c` で送信前に編集） |
| `C-c C-k` | レビューとコメントを破棄 |
| `q` | レビューを終了 |
| `?` | ヘルプ全体を表示（再度押すと非表示） |

コメントの扱いは diff バッファとほぼ同じですが、コメントは 1 行ではなく差分全体に属します。ファイル名と行番号が含まれ、セッションに送信されるプロンプトも同じ形式です。Claude のコメントは diff バッファにだけ表示されます。コメントの送信、`C-c C-k`、`q` のいずれを実行しても、レビューを開く前のウィンドウ構成に戻ります。ここには `g` コマンドはありません。レビューを更新するには、一度終了して再度開いてください。

## 適用前の提案をレビューする

![提案されたファイル変更内容を専用バッファで直接修正し、修正後の内容で許可する様子](../../../../assets/proposal.gif)

トランスクリプト上でリクエストが承認待ちのとき、リクエストノードで `c` を押すとその変更をレビューでき、`e` を押すと提案された内容が開きます（詳細は [プロンプトとトランスクリプト](/emacs-claude-code/ja/features/prompt/#回答待ちリクエストノード上での操作) を参照）。

ここでのコメントは **拒否の理由** として送信され、ファイル書き込み後に修正させるのではなく、事前に Claude へ再提案を促せます。

`e` を押すと対象ファイルのメジャーモードで提案が開きます。`C-c C-c` は Claude の提案の代わりに編集後のテキストで変更を許可し、変更箇所の diff を添えて送信します。`C-c C-k` はリクエストを保留のままにします。

## プランモード

プランモードを抜けると計画がリクエストとして送信され、ecc はそれをセッションの横の編集可能なバッファで開きます。

![プランが専用バッファで開き、権限モードを選択して計画を承認する様子](../../../../assets/plan.gif)

フィードバックの方法は 3 通りあります。行コメント（`C-c C-a`、削除は `C-c C-r`）、行内の `@claude: …` マーカー、計画自体の編集（`C-c C-d` で差分を表示）です。

フィードバックがある場合は `C-c C-c` でそれを添えて計画を差し戻し、再提案を求めます。フィードバックがなければ計画を承認し、権限モードの選択を求めます。`C-c C-p` で選択できるほか、指定しない場合は `ecc-plan-default-mode`（既定値: `"acceptEdits"`）が使用されます。

| キー | 動作 |
|---|---|
| `C-c C-c` | 承認、フィードバックがあればそれを送信 |
| `C-c C-k` | 理由を添えて却下（フィードバックも含める） |
| `C-c C-a` / `C-c C-r` | 現在行にコメントを追加 / 削除 |
| `C-c C-d` | 提案された計画に対する編集差分を表示 |
| `C-c C-p` | 承認後の権限モードを選択 |
| `C-c C-n` | 前回の計画から変更された次の行へ |

再提案されたプランでは、変更された行がマージンにマークされ、ヘッダーラインに `+N −N` が表示されます。

## 変更ファイル一覧 (Files セクション)

![トランスクリプト末尾の変更ファイル一覧: ファイルを展開して差分を確認し、単体レビューへ進む様子](../../../../assets/files.gif)

トランスクリプトの末尾には、セッション中に操作されたファイルが一覧表示されます（ファイルパス、`R×n` 読み込み／`E×n` 編集／`W×n` 書き込みの各操作、`+n −n` の変更行数）。`TAB` でそのファイルの累積 diff を展開し、`RET` でファイルを開き、`d` で単体レビューを行えます。

トランスクリプトで `f`（メニューでは `F`）を押すとこのセクションへジャンプします。`ecc-render-summary-position` を `'top` に設定すると、末尾ではなく先頭に配置されます。

## タイムライン

トランスクリプトで `T` を押すと、各ターンがプロンプト一覧で表示され、選んだターンへジャンプします。`C-c C-n` と `C-c C-p` でターンを前後に移動できます。

![タイムライン: 各ターンのプロンプト一覧から目的のやりとりにジャンプする様子](../../../../assets/timeline.png)

## レビュー表示時のウィンドウ配置

レビューには画面スペースが必要です。次の 2 つの変数でウィンドウの表示やフォーカスを制御できます:

| 変数 | 説明 |
|---|---|
| `ecc-window-hide-on-review` | `'project` でこのプロジェクトのセッションを非表示、`'all` で全セッションを非表示、`nil` でそのまま維持 |
| `ecc-window-review-focus` | `'review` でレビューバッファにフォーカス、`'session` でトランスクリプトにポイントを維持、`nil` で元のフォーカスのまま |

非表示のウィンドウは保存されません。`C-c c V`（`ecc-space-reset-windows`）でタブ全体を配置し直せます。セッションを 1 つずつ戻すなら `C-c c v` です。その他の設定は [設定リファレンス](/emacs-claude-code/ja/reference/configuration/) をご覧ください。
