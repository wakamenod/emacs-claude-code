`C-c ?` を押すと Transient メニューが開きます（Magit と同じメニューライブラリ [transient](https://magit.vc/manual/transient/) を使っています）。ecc のすべてのコマンドが並んでいます。

![セッション画面の下に開いた Transient メニュー: Session, Send, Review, Respond, View, Config の6 つのグループが表示されている様子](../../../../assets/menu.png)

各行にキーとコマンドが表示されます。`C-g` でメニューを閉じます。`-` で始まる行はスイッチで、そのあとに実行するコマンドのオプションを切り替えます。

セッションバッファの外では、`M-x ecc-menu` か、`ecc-global-map` の `?` でメニューを開きます（[グローバルキーバインド](/emacs-claude-code/ja/reference/key-bindings/)を参照）。どちらから開いても、キーの意味は同じです。

:::note[操作対象のセッションの決まり方]
メニューは、現在のバッファに結び付いたセッションを対象にします。結び付いたセッションがなければ、そのプロジェクトにただ1 つあるセッション、画面にただ1 つ表示されているセッション、最後に使ったセッションの順に選びます。決められないときは一度だけ尋ね、その答えをそのバッファに記憶します。
:::

## Session グループ

### `c` — セッションの開始 (Start)

現在のバッファのプロジェクトでセッションを開始します。セッション名はそのディレクトリ名になります。同じプロジェクトで2 つ目以降のセッションを開始するときは、名前を尋ねられます。`C-u c` では、ディレクトリと名前の両方を尋ねられます。

### `r` — セッションの再開 (Resume)

再開できる会話の一覧を表示します。

![会話再開ピッカー: 5 つの会話とそれぞれの状態アイコンが並んでいる様子](../../../../assets/resume.png)

| アイコン | 状態 |
|---|---|
| ▶ | この Emacs で実行中のセッション |
| ● | この Emacs にある、終了したセッションのバッファ |
| ◉ | 別のプロセスで実行されている会話 |
| ↺ | ディスク上に記録された会話 |

各項目には名前、最後に使った時刻、ディレクトリ（記録の場合は最初のプロンプト）が表示されます。`-f` スイッチを付けると、選んだ会話を続けるのではなく、そこから新しい会話を分岐させます。キーバインドでは、`C-c c r` でそのまま再開し、`C-u C-c c r` で分岐させます。

:::caution[実行中のセッションを再開すると履歴が分岐します]
CLI はファイルをロックしないため、2 つのプロセスが同じセッション ID に同時に書き込むと、記録を壊すおそれがあります。この状態は ◉ で示され、ecc は再開する前に確認を求めます。
:::

### `k` — セッションの終了 (Kill)

プロセスを停止し、セッションのバッファを kill します。記録はディスクに残るので、あとから `r` で再開できます。

### `R` — セッション名の変更 (Rename)

セッションとそのバッファの名前を変更します。新しい名前はタブ、モードライン、選択メニューに反映されます。

### `v` — プロンプトへフォーカス (Focus prompt)

セッションのウィンドウを表示し、ポイントをプロンプトの入力領域に移動します。

### `i` — 実行中断 (Interrupt)

実行中のターンを中断します。それまでに終わった作業は残ります。

### `t` — ターミナルへ引き渡し (Hand over to terminal)

会話を [ghostel](https://github.com/dakra/ghostel) に引き渡します。ghostel は CLI 本来の画面を Emacs のバッファの中に表示します。

<Video name="handover" label="セッションがターミナルへ引き渡され、CLI 本来の画面が表示されて会話が継続される様子" />

履歴が分岐しないように、ecc はターミナルがセッションを再開する前にターンを中断し、自分のプロセスを止めます。ターミナルが動いている間も、トランスクリプトはその進行を追い続けます。

### `u` — セッションの回収 (Reclaim session)

ターミナルで増えたやりとりを取り込み、Emacs でセッションをヘッドレスで再開します。ターミナルがまだ動いていれば、セッションはそちらに残り、ターミナルの終了とともに自動で Emacs に戻ります。

## Send グループ

これらのコマンドはソースコードのバッファから実行します。対象のセッションにコンテキストを送り、実行中のターンは中断しません（あとから送ったプロンプトはキューに入ります）。

### `s` `x` `g` `f` — バッファからの送信

| キー | 送信内容 |
|---|---|
| `s` | ミニバッファで入力した 1 行の指示のみ |
| `x` | 入力した 1 行と、現在のファイル名と行番号 |
| `g` | 選択中のリージョン（未選択時はバッファ全体）を引用ブロックとして添付 |
| `f` | ファイルのパスを `@path` 参照として送り、CLI に読ませる |

<Video name="send-region" label="リージョンの送信: 選択したコードと質問がトランスクリプトに届き、回答がストリーミングされる様子" />

`x` と `g` が付け加えるコンテキストは、次のようなブロックになります:

````
---
Current context: hello.py L1-L3
```python
def greet(name):
    return "hello " + name
```
````

プレフィクス引数を付けると、コードの前に添える指示を尋ねられたり（`C-u g`）、送信先のセッションを尋ねられたり（`C-u s`）します。CLI はディスクからファイルを読むので、`f` は送信前にバッファを保存するかを尋ねます。

### `e` — ポイント位置のエラーを修正 (Fix error at point)

現在の行の診断を、周りのコードと一緒に送信します。診断は Flymake、Flycheck、ポイント位置のオーバーレイのヘルプテキストの順に探します。

<Video name="fix-error" label="チェッカーが警告を出している行で診断が送信され、修正案が承認待ち編集として返ってくる様子" />

### `l` — インラインで質問 (Ask inline)

リージョンやファイルについて質問し、回答をトランスクリプトではなく、ポイントのすぐ上のオーバーレイに表示します。`n` と `p` でスクロール、`r` で続けて質問、`q` で閉じます。

<Video name="inline" label="ミニバッファで質問を入力し、コード上にオーバーレイとして回答がポップアップする様子" />

質問は、専用の軽いセッションか、フォークしたセッションで処理されます。どちらにするかは一度選ぶと、バッファごとに記憶されます。

### `w` — リージョンの書き換え (Rewrite region)

選択したコードを指示に従って書き換えます。書き換え案がその場に表示され、`RET` で確定するまでバッファは変わりません。

<Video name="rewrite" label="元のコードの上に書き換え案が表示され、RET で承認してバッファへ反映される様子" />

これはツールを使わない1 回きりの処理です。CLI が置き換え後のコードを返し、Emacs がバッファを直接書き換えます。

## Review グループ

`D` はレビューのメニューを開き、何と比べるかを選びます。セッションの変更、未コミット・ステージ済み・未ステージの変更、このブランチ、コミット、範囲から選べます。`F` と `P` は Files と Plan のセクションに移動し、`T` は指定したターンに移動します。

詳細は [レビューとプランモード](/emacs-claude-code/ja/features/review/) をご覧ください。

## Respond グループ

`a` と `d` は最も古い待機中のリクエストを許可または拒否し、`A` は待機中のリクエストをすべて許可します。`n` と `N` は次の待機中のセッションに移動し、`1`–`4` は質問の選択肢を選びます。

詳細は [プロンプトとトランスクリプト](/emacs-claude-code/ja/features/prompt/) をご覧ください。

## Spaces グループ

`j` は Space を切り替えます。`b` はサイドバーを開きます。`z` は現在のウィンドウをタブいっぱいに広げ、もう一度押すと元に戻します。`V` はこの Space のウィンドウを、新しいタブと同じ配置に戻します。`X` はこの Space を閉じ、実行中の処理をすべて停止します。

`W` は worktree メニューを開きます。このメニューでは、`c` で worktree を作ってそこでセッションを開始し、`o` で既存の worktree でセッションを開始し、`k` で worktree を削除します。

[Space と worktree](/emacs-claude-code/ja/features/spaces/) を参照してください。

## View グループ

### `B` — ダッシュボード (Dashboard)

動いているすべてのセッションを 1 か所で確認します。
詳細は [セッション管理](/emacs-claude-code/ja/features/sessions/) をご覧ください。

### `C` — ケイパビリティ (Capabilities)

使えるスキル、サブエージェント、スラッシュコマンド、MCP サーバー、プラグインを確認します。
詳細は [その他の機能](/emacs-claude-code/ja/features/other/#ケイパビリティ-能力一覧) をご覧ください。

### `h` — 履歴 (History)

`~/.claude/projects` に記録された過去の会話を、普通のセッションバッファで開きます。読み取り専用で見るか、`r` で再開します。

### `/` — 検索 (Search)

現在のプロジェクトの過去の会話をプロンプトと回答の本文で検索し、見つかったセッションに移動します。
詳細は [セッション管理](/emacs-claude-code/ja/features/sessions/#過去の会話を検索する) をご覧ください。

### `U` — 使用量 (Usage)

プランの使用量とレート制限を確認します。
詳細は [その他の機能](/emacs-claude-code/ja/features/other/#使用量レポート) をご覧ください。

### `L` — ログ (Log)

生の JSON プロトコルのログをタイムスタンプ付きで表示します（受信は `<<`、送信は `>>`）。トラブルシューティングやバグ報告では、まずこのバッファを見ます。

## Config グループ

### `m` — モデル変更 (Model)

実行中のセッションのモデルを、再起動せずに切り替えます。

### `p` — 権限モード (Permission mode)

実行中のセッションの権限モードを切り替えます。セッションバッファでは `S-TAB` で直接切り替えられます。

### `o` `O` `K` — リモートコントロール (Remote Control)

`o` はこのセッションの Remote Control をオン・オフします。オンにすると、Claude の Web アプリやデスクトップアプリからこのセッションを操作できます。`O` はブラウザで claude.ai/code のこのセッションを開き、`K` はその URL をキルリングにコピーします。`O` と `K` には、セッションがブリッジに接続されていることが必要です。

すべての設定は `M-x customize-group RET ecc` で変更でき、[設定リファレンス](/emacs-claude-code/ja/reference/configuration/)でも確認できます。
