## ケイパビリティ (能力一覧)

Transient メニューで `y` を押すか、ダッシュボードで `C` を押すと、CLI が `system/init` で報告したセッションのアクティブな能力一覧（スキル、サブエージェント、スラッシュコマンド、MCP サーバー、プラグイン）を確認できます。項目は提供元（プロジェクト、ユーザー設定、プラグイン、または CLI 組み込み）ごとにグループ分けして表示されます。

![ケイパビリティバッファ: 各グループが開閉されている様子](../../../../assets/capabilities.gif)

`TAB` でグループの折りたたみ、`RET` でポイント位置の項目の詳細表示、`g` で情報の再取得が行えます。初回のターンが完了する前はまだ報告データが存在しないため、バッファ上にその旨が表示されます。

## プラグイン (Plugins)

プロンプト領域で `/plugins` と入力するか、Transient メニューで `I` を押すか、
`M-x ecc-plugin` を実行すると、プラグインの一覧・導入・管理が行えます。
`/plugins` は Emacs 側で処理されるためモデルには送信されません。後ろに文字列を
付けると絞り込んだ状態で開きます（例: `/plugins mcp`）。CLI 本体の `/plugins` はターミナルクライアントが自前で
描画する画面であり、スラッシュコマンドではないため stream-json 経由では送信できません。
この機能は `claude plugin` サブコマンドを用いた ecc 版の同等機能です。

バッファは 4 つのタブで構成され、`TAB` / `S-TAB` で移動、`1`–`4` で直接選択できます。

| タブ | 内容 |
|---|---|
| Discover | 登録済みマーケットプレイスが提供する全プラグイン（説明・インストール数つき） |
| Installed | 導入済みプラグイン**とスキル**を 1 つのリストに。取得元ごとにグループ化され、無効なものは折りたたまれる |
| Marketplaces | 登録済みマーケットプレイスと、追加用の行 |
| Errors | 失敗したサブコマンド、およびディレクトリが消えた導入済みプラグイン |

| キー | 動作 |
|---|---|
| `s` | 検索。入力するそばから行が絞り込まれる（`C-g` で元に戻る） |
| `/` | 補完で目的の行へジャンプ。297 件のプラグインはこちらが速い |
| `RET` | プラグインの詳細表示、スキルの `SKILL.md` を開く、またはグループの折りたたみ |
| `i` | ポイント位置のプラグインを導入（スコープ: user / project / local） |
| `SPC` または `e` | ポイント位置のプラグインまたはスキルの有効・無効を切り替える |
| `E` | 状態を名前で選んで設定する（スキルには 4 状態ある） |
| `u` | ポイント位置のプラグイン、またはマーケットプレイスを更新 |
| `d` | ポイント位置のプラグインを削除、またはマーケットプレイスを登録解除 |
| `a` | リポジトリ・URL・パスからマーケットプレイスを追加 |
| `p` | 不要になった自動導入プラグインを削除 |
| `g` | すべて再取得 |

各タブの上部には検索行が、ヘッダー行にはそのタブのキー一覧が表示されます。ヘッダー行はスクロールしても消えません。

スキルの状態は 2 つではなく 4 つです。`on`、`name-only`（説明文なしで一覧に載る）、`user-invocable-only`（モデルからは隠れるが `/name` では呼べる）、`off`（両方から隠れる）。`SPC` は `on` と `off` を往復し、`E` は 4 つから選んで設定します。

スキルは `~/.claude/skills`、プロジェクトの `.claude/skills`、および各導入済みプラグインの `skills/` から読み取ります。組み込みスキルはディスク上のどこにも存在せず、`system/init` の `skills` が唯一の情報源なので、セッションが 1 回以上応答した後に表示されます。スキルの無効化にはサブコマンドがないため、ecc が設定ファイルの `skillOverrides` を書き換えます。CLI はこのキーを複数の設定スコープ間で**最も制限の強い値**でマージするため、プロジェクト側で無効化されたスキルをユーザー設定で有効にはできません（その場合は ecc がその旨を告げます）。

起動済みのセッションは起動時のプラグイン構成を保持し続けるため、変更後には実行中の
セッションへ `/reload-plugins` を送るかどうかを尋ねます。この挙動は
`ecc-plugin-reload-sessions` で、確認する（既定）・常に送る・送らない、から選べます。

本家には 5 つ目のタブ Stats があります。セッションが読み込んだスキルと、1 週間でそれぞれに計上されたトークン数の表ですが、これはローカルセッションを走査して算出されており、公開されていません。名前だけ同じ別物を置くよりはと考え、ここに Stats タブはありません。プラグイン単位の構成要素とコストは `RET` の詳細画面で見られます。本家の Errors タブが表示するプラグイン読み込みエラーも公開されていないため、このタブには Emacs 自身が確認できる内容のみを表示します。

`ecc-disabled-plugins` はこれとは別の仕組みです。ターミナルクライアント側には影響を
与えず、ecc が起動するセッションに対してのみプラグインを無効化します。この一覧に含まれる
プラグインは Installed タブで区別して表示されます。

## 使用量レポート

Transient メニューで `U` を押すか、`C-c c U`、または `M-x ecc-usage` を実行すると、Claude Code プランの使用量とレート制限の状況を確認できます。

![使用量レポートのポップアップ: レート制限枠、セッションのコスト、制限を消費している要因が表示されている様子](../../../../assets/usage.png)

表示される数値は CLI から直接取得したものであり、Web クライアントの「Settings → Usage」に表示されるものと同一です（Emacs 側で独自に推計したものではありません）。セッションが動作していない状態でも、ecc はバックグラウンドで一時的な問い合わせプロセスを起動して即座に終了するため、プロンプトを消費せずコスト 0 で安全に確認できます。

| キー | 動作 |
|---|---|
| `g` | 使用量メトリクスを再取得 |
| `b` | レート制限を消費している詳細内訳の表示/非表示を切り替え |
| `q` | レポートを閉じる |

`ecc-usage-display` を設定することで、レポートをフレーム上に浮かぶポップアップ（posframe）で表示するか、通常のウィンドウで表示するかを選択できます。消費要因の内訳スキャンは **このローカルマシン** に保存されているセッション履歴を対象とするため、別端末や claude.ai 上での消費は含まれません。

すべての設定オプションは [設定リファレンス](/emacs-claude-code/ja/reference/configuration/) に掲載されています。
