**Space** は、専用の Emacs タブを持つプロジェクトです。タブは、フレームのウィンドウ配置に名前を付けたものです。フレーム上端の帯を出すかどうかは [`tab-bar-show`](#タブバーを出すかは自分で決める) で決まります。git worktree はそれ自体が 1 つの Space になり、元のリポジトリの下に表示されます。

[`ecc-use-spaces`](/emacs-claude-code/ja/reference/configuration/#ecc-use-spaces) はデフォルトでオンです。オフにすると以前の配置になります。トランスクリプトはサイドウィンドウに表示され、タブ、サイドバー、worktree のコマンドはありません。

```elisp
(setq ecc-use-spaces nil)
```

## Space の仕組み

![すべての Space とセッションを並べたサイドバー、プロジェクトごとのタブ、ソースと 2 つのトランスクリプトが横に並んだ 1 つの Space](../../../../assets/spaces.png)

```
┌ *ecc-sidebar* ─────┬ タブバー: [ecc] [herdr] [feat-x] ───────────────────┐
│ Spaces             │ ┌ ソース ─────────┬ session-A ────┬ session-B ────┐ │
│ ⚠ [1] ecc        ▾ │ │                 │ (タブライン)  │ (タブライン)  │ │
│    main ↑2 ↓0      │ │                 │               │               │ │
│   └─ ▶ [2] feat-x  │ │                 │               │               │ │
│ · [3] herdr        │ └─────────────────┴───────────────┴───────────────┘ │
│    master          │                                                     │
│                    │   1 つの Space = 1 つのタブ = 1 つのウィンドウ配置  │
│                    │                                                     │
│ Sessions           │                                                     │
│ ⚠ ecc   waiting    │                                                     │
│ ▶ ecc-2 running    │                                                     │
│ · herdr    idle    │                                                     │
└────────────────────┴─────────────────────────────────────────────────────┘
```

トランスクリプトは横に並びます。最初の1つはソースの右隣に開き、そのあとは一番右のウィンドウを分割していきます。上下に積まれることはありません。開いたあとは普通のウィンドウなので、分割・移動・拡大・クローズを自由に行えます。タブはウィンドウ構成なので、Space を離れて戻ってくると配置が元に戻ります。トランスクリプトのタブラインでは、これまでどおりそのプロジェクトのセッションを切り替えられます。

トランスクリプトの幅が `ecc-space-session-min-width` より狭くなることはありません。横に空きがなくなると、最も長く操作していないセッションがウィンドウを明け渡し、ウィンドウのないまま実行を続けます。そのセッションはサイドバーか `C-c c V` で戻せます。

何も動いていない Space に移動すると、そこでセッションが始まります。これはデフォルトでオンの [`ecc-space-always-session`](/emacs-claude-code/ja/reference/configuration/#ecc-space-always-session) の働きで、この設定は最後のセッションを kill したときに Space を閉じもします。以前の会話を続けるには、開いたセッションで `/resume` と入力します。オフにすると、Space はソースだけで開き、そのプロジェクトの最後のバッファを kill するまで残ります。

| キー | コマンド | 動作 |
|---|---|---|
| `C-c c j` | `ecc-space-goto` | Space を名前で指定して移動。記録しか残っていないプロジェクトも対象 |
| `C-c c z` | `ecc-space-zoom` | このウィンドウでタブ全体を埋める。同じキーを押すと元の配置に戻る |
| `C-c c V` | `ecc-space-reset-windows` | この Space を新規タブの初期配置（左にソース、その隣にトランスクリプト）に戻す |
| `C-c c ?` → `X` | `ecc-space-close` | この Space を閉じ、その中で動いているものをすべて止める（リポジトリならその worktree も含む）。そのあと、閉じた worktree を削除するか尋ねる |
| — | `ecc-space-jump` | サイドバーの番号で N 番目の Space に移動 |

### タブバーを出すかは自分で決める

`tab-bar-mode` はタブの上に帯を描くだけで、ecc がこのモードを有効にすることはありません。有効にするのは `tab-bar-new-tab` で、`tab-bar-show` がデフォルトの `t` なら有効にし、`nil` に設定していれば無効のままにします。

```elisp
(setq tab-bar-show nil)   ; フレーム上端に帯を出さずに Space を使う
```

帯を隠しても、タブの作成・名前付け・切り替え・クローズはまったく同じように行われ、サイドバーがタブの一覧になります。

## サイドバー

![サイドバー: 2 つのプロジェクトと、その一方のリポジトリの下に並ぶ 2 つの worktree、下半分に各セッションの状態](../../../../assets/sidebar.png)

`C-c c b`（`ecc-sidebar-focus`）でサイドバーを開き、ポイントをそこへ移します。同じキーでポイントが元に戻ります。

上半分は Space の一覧です。各行には Space の状態を示す印、`1`–`9` キーに対応する番号、Space 名が表示されます。リポジトリの下にはブランチと upstream との差が表示され、その下に worktree がツリーの線でぶら下がります。worktree の名前はそのブランチ名です。`TAB` で worktree を折りたためます。

下半分はセッションの一覧で、それぞれの印、名前、何を待っているかが表示されます。印、色、点滅はタブラインと同じなので、セッションはどこに表示されても同じ見た目です。

| キー | 動作 |
|---|---|
| `RET` | その行の Space またはセッションへ移動 |
| `n`, `p` | 次の行／前の行 |
| `TAB` | リポジトリの worktree を折りたたむ／展開する |
| `1`–`9` | その番号の Space へ移動 |
| `c` | この Space でセッションを開始 |
| `W` | この Space から worktree を作成してセッションを開始 |
| `k` | このセッションを停止 |
| `K` | この worktree のディレクトリを削除 |
| `X` | この Space を閉じる |
| `a`, `d` | このセッションが待っているものを許可／拒否（先に確認する。`Bash` は対象外） |
| `g` | git の状態を更新して再描画 |
| `q` | サイドバーを隠す |

`a` と `d` の動作はダッシュボードと同じです（[セッション管理](/emacs-claude-code/ja/features/sessions/)を参照）。`ecc-sidebar-width` はサイドバーの幅（桁数）で、デフォルトは 28 です。`ecc-sidebar-sessions-sort` は下半分の並び順を決めます。`spaces`（デフォルト）はセッションをそれぞれの Space の下に置き、`priority` は応答を待っているものを先頭にします。

## worktree

git の worktree は、リポジトリに別のブランチを割り当てたもうひとつの作業ツリーです。2 つのセッションが互いの変更を見ずに同じプロジェクトで作業できます。以下のコマンドは `ecc-use-spaces` のオン・オフを問わず使えます。

| キー | コマンド | 動作 |
|---|---|---|
| `C-c c ?` → `W c` | `ecc-start-worktree` | リポジトリの隣にブランチをチェックアウトしてセッションを開始 |
| `C-c c ?` → `W o` | `ecc-start-in-worktree` | 既存の worktree でセッションを開始 |
| `C-c c ?` → `W k` | `ecc-remove-worktree` | worktree 内のセッションを停止して worktree を削除 |

`ecc-start-worktree` はブランチを尋ね、既存のブランチを候補に出します。既存のブランチはそのままチェックアウトし、存在しないブランチは `HEAD` から作ります。別の worktree がすでに使っているブランチでも拒否はせず、確認したうえでその worktree でセッションを始めます。worktree はブランチで探すので、ディレクトリ名は何でも構いません。

worktree は `ecc-worktree-directory`（デフォルトは `.claude/worktrees`）に置かれます。相対パスならリポジトリの下になり、`feat/x` の worktree は `<repo>/.claude/worktrees/feat-x` に置かれます。絶対パスならすべてのリポジトリで共有され、worktree は `<directory>/<repository>/<branch-slug>` に置かれます。

worktree で動く最後のセッションが終わると、どう終わったかにかかわらず、ecc はその worktree を削除するか尋ねます。**ブランチが削除されることはありません**: `ecc-remove-worktree` が削除するのはディレクトリだけなので、コミット済みの変更が失われることはありません。未コミットの変更や未追跡のファイルがあって git が削除を拒んだときは、ecc がディレクトリ名を示してもう一度尋ね、そこで初めて強制的に削除します。

## 作業を worktree のセッションに引き渡す

セッションに worktree での作業を頼むと、CLI は単独では `git worktree add` を実行し、同じ会話のまま作業を続けます。1 つのセッションで 2 つの worktree を扱うことになります。

[Emacs の MCP サーバー](/emacs-claude-code/ja/start/installation/)が有効な場合（`ecc-mcp-enabled`）、モデルには代わりに `start_worktree_session` が提示されます。モデルがブランチ名を決めて依頼文を書くと、Emacs が worktree を作成して Space として開き、そこでセッションを開始してその依頼文を送ります。Emacs は、会話の中で見たこと（触れたファイル、書いたプラン、記録ファイルのパス、まだコミットされていない変更）を依頼文に書き足します。worktree は `HEAD` から作られるので、その作業は先にコミットするか、依頼文にそう書いてください。モデルがツールを呼ばずに自分で worktree を作ろうとすると、Emacs はその要求を拒否し、ツールを使うよう伝えます。このとき権限の確認は表示されません。

下書きに worktree という言葉があると、ツールのことをモデルに思い出させる 1 行を添えて送ります。この行はユーザーが書いたものではないので、トランスクリプトではプロンプトから外し、その下に "1 line Emacs added" として折りたたんで表示します。

モデルの指定したブランチが別の worktree でチェックアウト済みのときは、ツールが拒否して別のブランチを求めます。2 つのセッションが 1 つの worktree を共有しないようにするためです。Lisp からは `ecc-worktree-delegate` で呼べますが、`M-x` のコマンドはありません。

worktree で始めたセッションは、元のリポジトリの下に専用の Space を開きます。
