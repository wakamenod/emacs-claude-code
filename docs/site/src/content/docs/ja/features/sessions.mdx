セッションは、実行中の `claude` プロセス、そのトランスクリプトバッファ、セッション名からなります。プロジェクトで最初のセッションには、自動でプロジェクトのディレクトリ名が付きます。2つ目以降は名前を尋ねられます。セッションバッファを kill すると CLI プロセスも止まりますが、会話の記録はディスクに残ります。

## セッションが始まる場所

`C-c c c`（`ecc-start`）は、現在のバッファのプロジェクトでセッションを開始します。そのバッファがファイルかディレクトリを開いていればそれを使い、そうでなければ直近にファイルかディレクトリを開いていたバッファを使います。トランスクリプト、ダッシュボード、ヘルプ、スクラッチバッファから開始した場合も、この直近のバッファに従います。プレフィクス引数を付ける（`C-u C-c c c`）と、そのプロジェクトをデフォルトにしてディレクトリを尋ねます。

セッションがどこで始まるかを確認してください。**セッションのディレクトリは CLI の起動時に決まり**、あとから変えられません。違うプロジェクトで始めてしまったら、セッションを kill して始め直すしかありません。開始したディレクトリはエコーエリアに表示され、ヘッダーラインには、セッションのある間ずっとプロジェクト名を表示します。

## 会話の再開

Transient メニューで `r` を押すか（[メニュー解説](/emacs-claude-code/ja/features/menu/#r--resume)）、`M-x ecc-resume-menu` を実行します。一覧には、この Emacs で動いているセッションが先に、続いてこのプロジェクトで記録された会話が、最近使った順に並びます。

![会話再開メニュー: 5つの会話とそれぞれの状態アイコンが並んでいる様子](../../../../assets/resume.png)

| アイコン | 状態 |
|---|---|
| ▶ | この Emacs で実行中のセッション |
| ● | この Emacs にある、終了したセッションのバッファ |
| ◉ | 別のプロセスで実行されている会話 |
| ↺ | ディスク上に記録された会話 |

各項目にはセッション名、最終更新日時、ディレクトリ（過去の記録の場合は最初のプロンプト）が表示されます。`-f` を付けると、選んだ会話をそのまま再開するのではなく、そこから新しい会話を分岐させます。

:::caution[実行中の会話を再開すると履歴が分岐します]
CLI はファイルをロックしないため、2つのプロセスが同じセッション ID に同時に書き込むと、記録を壊すおそれがあります。この状態は ◉ で示され、ecc は再開する前に確認を求めます。
:::

セッションの記録は Claude Code が `~/.claude/projects` の下に保存するので、ターミナルの CLI で始めた会話もここに並びます。記録はそれぞれ会話のツリーになっていて、編集、中断、再開のたびに新しいブランチができます。

`h` ではプロセスを起動せずに記録を読めます。そのバッファで `r` を押すと再開します。CLI プロセスが予期せず終了したときは、ecc が再開するかを尋ねます。

## 再起動後にセッションを復元する

ecc は、開いている Space とセッションを `user-emacs-directory` の `ecc-state.eld` に保存します。セッションを開始・終了したときと、タブを開閉したときに書き直すので、Emacs がクラッシュしてもファイルは最新の状態です。このファイルに書き込むのは、自分のセッションを持ったことがあるか、`ecc-restore` を実行した Emacs だけです。タブを開いたり記録を閲覧したりしただけの Emacs は、ファイルに手を付けません。

`M-x ecc-restore` で復元します。

- Space は元のタブの順に開き、各 Space のセッションは横に並びます。`ecc-use-spaces` がオフのときは、セッションだけが戻ります。
- 各セッションは記録から読み込まれ、停止した状態で戻ります。CLI が起動するのは、プロンプトを送るか `R` を押したときです。同じ会話が別のプロセスで動いていないかも、そのときに確認します。
- すでに開いているセッションは飛ばすので、2 回実行しても問題ありません。`h` で閲覧用に開いた記録は、開いているとは数えません。そのバッファのまま、復元したセッションになります。
- ディレクトリがなくなったセッションや Space は飛ばし、メッセージで知らせます。

自分で kill したセッションはファイルから外れるので、戻るのは Emacs を終了したときに開いていたものです。前の Emacs が保存し、まだ復元していないセッションは、復元するまでファイルに残ります。先に別のセッションを始めても、復元せずに Emacs を終了しても消えません。起動のたびに復元するには、init ファイルから `(ecc-restore)` を呼び出してください。

## 過去の会話を検索する

セッション名ではなく話した内容を覚えているなら、メッセージの本文で過去の会話を検索できます。Transient メニューで `/` を押すか、`C-c c /`、または `M-x ecc-search` を実行します。現在のプロジェクトで一致した会話が新しい順に、一致した行と前後の文脈とともに表示されます。`RET` か `o` でポイント位置の会話を開きます。プレフィクス引数（`C-u`）を付けると、現在のプロジェクトではなく全プロジェクトを検索します。

```
3 sessions said permission prompt in ~/Projects/emacs-claude-code/

Permission prompt rendering  2026-09-08 14:07  2d4f54c9  2 hits
    › how does the permission prompt decide which diff to show?
    ‹ …the block is drawn by `ecc-perm.el`, and a permission prompt keeps the tool input…

Dashboard columns  2026-09-06 10:22  f6743727  1 hit
    ‹ …an idle row is dimmed, and a permission prompt puts `!` in the gutter…
```

`›` はユーザーのプロンプト、`‹` は Claude の回答を表します。各ブロックの見出しには、会話のタイトル、最終更新日時、短縮したセッション ID、一致した件数が表示されます。

| キー | 動作 |
|---|---|
| `RET` / `o` | ポイント位置の会話の記録を開く |
| `n` / `p` | 次 / 前のセッションへ移動 |
| `g` | 同じ文字列で再検索 |

検索するのは会話のテキスト、つまりユーザーのプロンプトとアシスタントの回答です。ツールの結果、ツール呼び出しの生の JSON、モデルが読んだファイルの内容は除いています。含めると、たまたまそのファイルを読んだセッションがすべてヒットしてしまうためです。検索は大文字と小文字を区別しない文字列の一致で、正規表現ではありません。

セッションの記録には数万件のメッセージが入っていることもあります。検索を速くするため、ecc はまず `rg` か `grep` で候補の記録ファイルを絞り込み、そのファイルの一致した行だけを解析します。記録が 100 件、合計 100 MB を超えるプロジェクトをまたいでも、検索は 1 秒もかかりません。どちらのコマンドも `PATH` になければ、記録を1つずつ直接読みます。時間はかかりますが、結果は同じです。

:::note[巻き戻し・破棄されたブランチも検索対象となります]
どのメッセージが今の会話の流れに属するかを決めるには記録全体を解析する必要があり、速い絞り込みではそれをしません。そのため、巻き戻したり破棄したりしたブランチの発言も検索結果に出て、そのセッションを開けます。
:::

## ダッシュボード

Transient メニューの `B`、`C-c c B`、または `M-x ecc-dashboard` でダッシュボードを開きます。

![ダッシュボード: 回答待ち、実行中、アイドル、終了済みの4つのセッションが一覧表示されている様子](../../../../assets/dashboard.png)

ダッシュボードには、この Emacs が管理しているすべてのセッションが並びます。内部の状態を直接読むので、ポーリングはしません。ほかのプロセスの会話やディスク上の会話は、`r` か `h` で開けます。

| 列 | 説明 |
|---|---|
| Name | セッション名（タブやモードラインに表示される名称） |
| State | 現在の動作と、ユーザーの入力を待っているか |
| Project | ディレクトリ名（ツールチップにフルパスを表示） |
| Model | CLI から報告された使用中モデル |
| Last prompt | 直近のターンで送信されたプロンプト |
| Updated | 最後の応答があった時刻 |
| Cost | ここまでの累計コスト |

応答待ちのセッションがいちばん上に、残りは最近動いた順に並びます。ガターには、ユーザーの応答を待っているセッションに `!`、画面に表示中のセッションに `▶` が付き、アイドルの行は薄く表示されます。ヘッダーラインには、状態ごとのセッション数、合計コスト、レート制限の残りが、CLI から受け取った情報をもとに表示されます。

| キー | 動作 |
|---|---|
| `RET` | 該当セッションへ移動 |
| `+` | 新しいセッションを開始 |
| `k` | セッションのプロセスを停止 |
| `D` | ディスク上のセッションの記録を削除 |
| `r` | セッション名を変更 |
| `R` | セッションを再開 |
| `a` / `d` | 待機中の最古のリクエストを許可 / 拒否 |
| `C` / `S` | セッションのケイパビリティ / スキルを表示 |
| `U` | 使用量とレート制限を表示 |
| `g` | ダッシュボードを再描画 |

`k` はプロセスを止めますが、記録はディスクに残るので、あとから `r` で再開できます。セッションを止めるとそのウィンドウとトランスクリプトも消えるため、先に確認を求めます。`D` は記録ファイルを完全に削除します。

`a` と `d` は、答える前に、何への応答かを確認します（`ecc-answer-confirm` を `nil` にすると確認しません）。また、`ecc-answer-exclude-tools`（デフォルトは `Bash`）に挙げたツールには答えません。シェルコマンドは、列の幅に切り詰めた要約からではなく、`RET` で開くトランスクリプトで読んで答えるものだからです。サイドバーの `a` と `d` も同じです。答えたときに何が送られるかは[プロンプトとトランスクリプト](/emacs-claude-code/ja/features/prompt/)を参照してください。

## タブライン

各セッションは、自分と同じプロジェクトのセッションウィンドウのタブラインにタブとして並びます。

![4つのタブが表示され、それぞれの動作状態に応じて色分けされているセッションウィンドウ](../../../../assets/tabs.png)

| マーク | 状態 | 表示色 |
|---|---|---|
| `⚠` | ユーザーの回答待ち | 点滅する警告ハイライト |
| `▶` | 処理中（作業中） | 緑 |
| `✗` | プロセス停止 | 赤 |
| `○` | `ecc-restore` で復元済み、まだ起動していない | 減光表示 |
| (なし) | アイドル（待機中） | 減光表示 |

そのウィンドウに表示中のセッションのタブは太字と下線になり、裏で処理中のセッションは落ち着いた緑で表示されます。点滅を止めるには `ecc-tab-blink` を `nil` にします。

タブは作成順に並ぶため、位置が変わりません。タブを `mouse-1` でクリックすると、ウィンドウがそのセッションに切り替わります。セッションバッファ内では、`C-c C-t`（`ecc-switch-session`）でそのウィンドウのほかのタブから選んで切り替えられます。`C-u C-c C-t` なら、すべてのセッションから選べます。`ecc-use-spaces` がオンのときに別のプロジェクトのセッションを選ぶと、このウィンドウではなく、そのプロジェクトの Space で開きます。`x` ボタンをクリックすると、セッションを終了するか尋ねます。ウィンドウはその場に残り、閉じたタブの隣（右、右端だった場合は左）のタブに切り替わります。同じフレームのほかのウィンドウがすでに表示しているタブは飛ばすので、同じトランスクリプトが 2 つのウィンドウに並ぶことはありません。ウィンドウが閉じるのは、表示するものが何も残らなくなったときだけです。

<Video name="switch" label="セッションウィンドウが別のセッションに切り替わり、選択タブが greet から notes へ移動してトランスクリプトが置き換わる様子" />

Emacs 全体のタブバー（tab-bar）にもセッションの状態を出すには、`ecc-tab-bar-state` を設定し、`tab-bar-tab-name-function #'ecc-tab-bar-tab-name` を使います。

ウィンドウのタブには、そのウィンドウ自身のプロジェクトのセッションだけが並びます。異なるプロジェクトのウィンドウを並べても、それぞれのタブ行は別々で、互いのセッションは現れません。すべてのセッションを 1 行に並べるには、`ecc-tab-line-scope` を `'all` に設定してください。

スコープ外のセッションにも、`C-u C-c C-t`（`ecc-switch-session`）、ダッシュボード（`C-c c B`）、`C-c c n`（`ecc-next-attention`）でアクセスできます。タブが画面にないので、応答待ちになっても点滅はしません。モードラインの `⚠ecc:N` の数と通知には、これまでどおり反映されます。

タブラインの下のヘッダーラインには、左にセッションの現在の状態、その隣にプロジェクト名、右にコンテキストウィンドウの残りが表示されます（残りが減ると黄色、赤へと変わります）。

## 1 つのプロジェクトに絞る

`M-x ecc-focus-project` は、ほかのプロジェクトのトランスクリプトで埋まったフレームを、1 つのプロジェクトだけの表示に戻します。何も kill せず、プロセスも停止しません。

Space を使うと、プロジェクトごとに専用のタブがあり、そのタブに切り替えれば同じことができます。[Space と worktree](/emacs-claude-code/ja/features/spaces/)を参照してください。

## 応答を待っているセッションの把握

- **モードラインの `⚠ecc:N`**: `N` は全セッションの待機中のリクエストの合計。クリックするとダッシュボードが開く
- **通知**: `ecc-notify-level`（`'message`, `'pulse`, `'desktop`, `nil`）と `ecc-notify-events`（ターン完了、待機中のリクエスト、プロセス終了）で設定
- **タブの表示**: 上で説明したタブのマーク

`n` と `N` は、次の待機中のリクエストに移動します（`n` は全体、`N` は現在のプロジェクト内）。どちらも `a`、`d`、`1`–`4` と同じく、`ecc-global-map` からどのバッファでも使えます。

3つの表示は、どれもデフォルトで有効です。

ここに出てきた設定の詳細は[設定リファレンス](/emacs-claude-code/ja/reference/configuration/)にあります。
