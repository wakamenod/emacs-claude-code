[Space](/emacs-claude-code/ja/features/spaces/) を使った作業の流れの一例です。プロジェクトを選んで会話を進め、実装を専用の worktree に任せ、終わったら両方を片付けます。

## プロジェクトへ移動する

`C-c c j`（`ecc-space-goto`）を押すと、どの Space に移動するか尋ねられます。候補は今開いているものだけではありません。ecc は CLI の会話記録を読むので、これまでにセッションを始めたことのあるプロジェクトがすべて候補に並びます。先月作業したきりで、プロセスもタブも残っていないプロジェクトにも `RET` ひとつで移れます。

選ぶと、その Space がサイドバーに加わり、そこでセッションが始まります。

<Video name="usecase-goto" label="一覧からプロジェクトを選択: 専用タブが現れ、サイドバーに行が追加され、ソースの隣にセッションが開く" />

## 会話する

セッションはプロジェクトのソースの隣に開きます。あとは普段どおり、質問し、読み、答えます。会話が実装の段階に入ったら、作業をこのウィンドウから切り出します。

「worktree を切ってそこでやって」のように worktree を頼みます。[Emacs の MCP サーバー](/emacs-claude-code/ja/start/installation/#mcp-サーバーの有効化)が有効（`ecc-mcp-enabled`）なら、Claude が `start_worktree_session` を呼び出します。Emacs は worktree を作り、リポジトリの下に専用の Space として開き、そこでセッションを始めて指示を渡します。元の会話には引き渡し先が報告され、会話はそのまま続きます。

![worktree が専用の Space になった状態: リポジトリの隣に並ぶタブ、サイドバーのリポジトリ下に追加された行、そこで動くセッション](../../../../assets/usecase-worktree.png)

## 片付ける

実装が終わったら、worktree のセッションのバッファを kill します。その Space にはほかに何もないので Space が閉じ、隣の Space に戻ります。このとき ecc は、worktree のディレクトリも削除するかを尋ねます。どちらを選んでもブランチは残ります。

## 終わった worktree をまとめて片付ける

バッファを kill して片付くのは worktree 1 つです。プルリクエストがマージされたあとなど、終わった worktree が複数あるときは、そのプロジェクトのどのセッションでも「終わった worktree を削除して」と頼みます。MCP サーバーが有効なら、Claude はリポジトリの worktree をそれぞれ確かめ、終わったものを削除します。worktree ごとの確認はありません。待機中のセッションは止まり、Space は閉じ、ブランチは残ります。`node_modules` など、git が無視するファイルも一緒に消えます。

そのあと Claude は、削除したものと、残したものとその理由を報告します。コミットしていない変更や追跡していないファイル、未保存のバッファや送っていない下書き、作業中のセッションがある worktree は残ります。ブランチがまだマージされていない worktree も残ります。条件の詳細は[終わった worktree を削除する](/emacs-claude-code/ja/features/spaces/#終わった-worktree-を削除する)にあります。ecc の外で起動した `claude` に必要な設定も同じ節にあります。
