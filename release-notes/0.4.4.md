Verified against **Claude Code CLI 2.1.290** and Emacs 30.1.

A release about how ecc is put together. No command, key or setting changes,
and a session looks and behaves as it did in 0.4.3.

### Loading ecc no longer advises Emacs

0.4.3 took ecc's functions off the hooks of Emacs. Two pieces of advice were
still put on Emacs's own functions as ecc loaded: one on the input-method
functions of the macOS port, which keep the prompt's placeholder right while
text is being composed, and on Emacs before 31, one on
`ediff-recenter-one-window`, which an ediff review needs when its keys are
typed in one of its windows. Each now goes on with the first chat buffer or
the first ediff review, and a test fails if loading any file of ecc advises a
function that is not ecc's own.

### The modules depend on each other one way

ecc is 54 files, and many of them used to reach up into the modules built on
them, or wait for one to load and then register with it. The lowest modules
now call nothing above them, no module registers with another through
`with-eval-after-load`, and no module learns at load time what to call through
a variable another one sets. The commands that start and stop a session moved
from `ecc.el` to a new `ecc-lifecycle.el`, and `ecc-review-direct.el` was
folded into `ecc-review-ediff.el`. Forward declarations went from 250 to 97,
and package-lint's warnings from 10 to 1.

### If you call ecc's internals

- `(require 'ecc-review-direct)` no longer works; require `ecc-review-ediff`.
  Every symbol keeps its name.
- `ecc-session-set-name` is an obsolete alias of `ecc-model-set-name`.
- `ecc-proc-start` takes the function that receives the CLI's messages as its
  second argument, and the variables `ecc-proc-message-function` and
  `ecc-mcp-config-function` are gone.
- Commands and options that moved between files keep their names and their
  autoloads.

Every source file now names all four models that wrote it in an `Assisted-by:`
line each.

`CHANGELOG.md` has the full record.
