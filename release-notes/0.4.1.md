Verified against **Claude Code CLI 2.1.290** and Emacs 30.1.

A documentation release. Nothing changes a command, a key or a setting. What it
touches is the file headers, the docstrings, and the wording of five error
messages.

### Every file names the assistance it was written with

Each source file now carries an `Assisted-by:` line under its `Author:` line.
The repository's history has said this in its commit trailers since the first
commit -- 431 commits name an assistant -- but a reader who has one file in
front of them, or the package as an archive serves it, could not see it. The
file header is the only place the fact travels with the code.

### Keys and messages read the way Emacs writes them

- Two mentions of `C-g` were plain text rather than keys, and two key sequences
  were quoted with the opening half only, which renders the closing quote as a
  stray character.
- Five error messages opened in lower case. `gh named no commits for pull
  request #N` now reads `No commits named by gh for pull request #N`. These are
  strings the code signals, not comments: a session that hits one sees the new
  wording.
- Three functions had a docstring that never named one of their arguments, a
  variable's first line was not a sentence, and a Lisp symbol was not quoted as
  one.

`CHANGELOG.md` has the full record.
