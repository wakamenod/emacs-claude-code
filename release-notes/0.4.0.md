Verified against **Claude Code CLI 2.1.281** and Emacs 30.1.

### Claude comments on the review

With the Emacs MCP server on (`ecc-mcp-enabled`), Claude can open the review of its session and read it through the `review_*` tools: `review_open`, `review_hunks`, `review_comment`, `review_comment_apply`, `review_navigate`, `review_list_comments`, `review_remove_comment` and `review_clear_comments`. It puts comments on lines or hunks of the diff you are reading, answers your comments with replies, and scrolls the review to the place it is talking about. It never writes or changes a comment of yours. The tools write no file, so they run without asking. Claude's comments have their own face, `ecc-review-agent-comment-face`, and `a` hides them. Claude opens the review when you ask for it. It opens beside the session without taking your window, and works the same in ediff.

In the review, `c` comments on the line at point -- the old side on a removed line, the new side on an added one, the whole hunk on the `@@` line -- and `{` and `}` move between comments. `T` asks Claude for a tour of the changes, `t` for the next stop, and `M` sends a question from the minibuffer, about the lines of the region when one is active.

An open review follows the files (`ecc-review-auto-refresh`): it reads the diff again when a tool of its session changes something and when a file of the repository is saved, and keeps your comments and your place.

### Choosing what to review

`C-c c D` opens `ecc-review-menu`, which asks what to compare before anything opens: `D` what changed since the session started (what `C-c c D` did before), `w` everything uncommitted, `u` what is not staged, `s` what is staged, `b` this branch against another, `c` a commit or a run of commits, `r` a range you type, and `p` a GitHub pull request when `gh` is on `PATH`. Each line says how many files it would show. `-f` narrows the review to some files and `-e` opens it the other way from `ecc-review-style`. `S` points the menu at another session or starts a new one, and the comments go to that session.

### Reading a pull request a commit at a time

After `p` picks a pull request, it asks whether to review the whole of it or one of its commits. `]` and `[` step to the next and previous commit in the same window, and each commit keeps its own comments. `C-c C-a` sends the comments of every commit as one prompt. A review whose right side is not checked out says so in its header line and in what it sends to Claude, which is told to ask before editing.

### The ediff review

- It opens with the old side above the new one and a reply pane on the right that shows Claude's latest turn as it streams (`ecc-review-ediff-layout`, `stacked`). `|` switches to side by side with the pane underneath. `y` answers a permission or a question Claude is waiting on without leaving the review.
- The keyboard is in the window of the new side, and every key of the control panel works in both windows. `c` in a window comments on the line at point, `x` removes a comment, and `RET` opens the file at that line. Moving point in one window brings the other side along. The control panel is out of sight; the keys are on the header lines, and `?` shows all of them.
- It opens faster (a review of 57 files went from 1.70 s to 0.33 s) and marks what changed inside every difference on the screen, not only the current one.

### Files and filtering

`s` in a review, diff or ediff, shows a list of its files beside the diff, with what happened to each, the lines added and removed, and the comments on it. `RET` there goes to the file. `/` keeps only the files whose path, or one of Claude's comments on them, contains what you type.

### Sending keeps the review open

`C-c C-c` sends your comments and leaves the review open, so Claude's replies land under them. Sent comments stay, dimmed, and the next `C-c C-c` sends only the ones made since.

### Elsewhere

- `M-x ecc-restore` brings back the Spaces and sessions that were open when Emacs last exited. They come back stopped, and a CLI starts when you send a prompt or press `R`.
- With the MCP server on, Claude lists the worktrees with `list_worktrees` and removes the finished ones, with their Spaces, with `remove_worktree`. It removes only a worktree with nothing to lose: no uncommitted or untracked files, no unsaved buffer or unsent draft, the branch's work merged, and no session at work in it. Files git ignores go with it, branches stay, and `ecc-worktree-auto-allow-removal` decides whether it asks first.
- A Bash command that changed files shows each file's diff under its output, as the CLI's own TUI does. In most sessions the CLI sends that diff only with `"bashEditDiffEnabled": true` in `~/.claude/settings.json`, which is a Claude Code setting that ecc does not set.
- `C-c C-y` in the prompt pastes the image on the clipboard as an `@` reference. On macOS, a screenshot is converted to PNG with `sips`.

### Breaking

- **`d` in an ediff review scrolls the reply pane** instead of removing a comment. `x` removes a comment there, and `C-u x` offers every comment of the review. The diff review keeps `d`.
- **`G` is gone from `C-c c` and `ecc-menu`.** `C-c c D w` is the same review. The command is now `ecc-review-range`; `ecc-review-worktree` and its related names remain as obsolete aliases, and `CHANGELOG.md` shows how to bind `G` again.
- **`ecc-review-ediff-layout` replaces `ecc-review-ediff-split-window-function`.** It takes `stacked` (the default) or `side-by-side`, the layout an ediff review had before; nil, ediff's own layout, is gone.

This release also has nine fixes; `CHANGELOG.md` has the full record.
