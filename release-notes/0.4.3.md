Verified against **Claude Code CLI 2.1.290** and Emacs 30.1.

A release about what ecc does when you are not looking at it. Nothing changes
a command, a key or a setting.

### Loading ecc no longer changes Emacs

Loading the package used to put nine of its functions on the hooks of Emacs
itself. Every file you saved, every window that changed, every buffer you
killed and every exit ran ecc code -- in an Emacs that had never started a
session. The worst of them walked every buffer in the Emacs on every save,
looking for a review to mark stale, whether or not a review had ever been
opened.

Each now goes on when what it serves first exists: the side-window watch with
the first window that has a role, the Space hooks with the first Space, the
review hooks with the first review, the saving of what is open with the first
session. The Emacs Lisp manual's conventions put it plainly -- "simply loading
a package should not change Emacs's editing behavior" -- and a test now holds
the line: it loads every file of ecc in an Emacs of its own and fails if any
ecc function is found on a hook that is not ecc's own.

### Errors are named instead of swallowed

Twenty-two of the twenty-three `ignore-errors` in ecc are gone. `ignore-errors`
catches everything, so a misspelled function or a wrong type was discarded as
quietly as the missing file the code was braced for. Where a predicate exists
the call is now guarded by it (`window-resizable-p`, `file-notify-valid-p`,
`iso8601-valid-p`); where the library offers a quieter form it is used
(`vc-responsible-backend` takes a NO-ERROR argument); where only a class can be
named, it is named (`file-error`, `json-error`); and three callers that only
read a settings file now pass a NOERROR argument to the reader instead of
burying its error, so the caller that writes the file still cannot write over
one it failed to read.

Reading a directory as a file does not signal the same thing on every Emacs --
29.4 reports it as a plain error rather than a `file-error` -- so the two places
that read a file by name ask whether it is a directory first.

The one `ignore-errors` left is in the header line: `project-current` runs
whatever other packages put on `project-find-functions`, and what those signal
is theirs to decide. The code says so where it stands.

### Three smaller defects

A `funcall` was handed a function name quoted as a symbol rather than as a
function, a docstring line opened with a parenthesis in column 0 -- which a
scan for the start of a top-level form reads as one -- and a point was moved
with `goto-char` where `beginning-of-line` says the same thing.

`CHANGELOG.md` has the full record.
