Verified against **Claude Code CLI 2.1.274** and Emacs 30.1.

A maintenance release: one bug you would only hit with an unusual setup, three
fixes you can see, and the packaging and documentation work that this
repository should have carried from the start. Nothing changes a command, a key
or a setting.

### If you set CLAUDE_CONFIG_DIR, ecc was reading the wrong directory

That variable moves the whole of `~/.claude` -- the recorded conversations, the
running sessions, the settings, the skills, the plugins, and the credentials
with them. ecc starts the CLI with the environment of this Emacs, so the
directory the CLI uses is the one this Emacs names; ecc read `~/.claude`
regardless, which is a directory the session it just started never touches. The
symptom was nothing to resume and nothing listed as running elsewhere, rather
than an error. The six directories now come from `ecc-config-directory`, and
the `.claude.json` that lists the projects follows the same move.

### The global modes can be turned on from an init file again

`ecc-notify-mode`, `ecc-tab-line-mode`, `ecc-pending-indicator-mode`,
`ecc-mcp-indicator-mode` and `ecc-track-source-buffer-mode` now carry autoload
cookies. A global mode is exactly the thing turned on from an init file or from
Custom before anything has loaded the file that defines it, and without the
cookie `(ecc-notify-mode 1)` there was a void function. Starting a session
turned them on either way, which is why this went unnoticed; an Emacs
configured to have them from the beginning now gets them.

### Reviewing in ediff

- **The difference you are standing on is visible.** A theme is free to paint
  the current difference in exactly the colours every other difference already
  has -- modus-vivendi does -- so nothing said where `n` had just arrived.
  There are two marks now: the current difference is carried five points of
  lightness away from the background and set in bold, and a bar is drawn in the
  fringe beside every one of its lines. A frame with no fringe gets one, in the
  review's own two windows only.
- **Quitting a review gives the cursor back.** The ediff control panel is a
  frame of its own, and taking it down left Emacs with no frame the window
  system considered focused -- which, with `cursor-in-non-selected-windows`
  nil, is no cursor drawn anywhere until something was clicked.

### Closing a tab keeps the window

The `x` of a tab stops the session behind it, and a stopped session's window is
deleted so that a row of transcripts is not left holding `*scratch*`. With a tab
line, losing one tab is no reason to lose the window: it now moves to the tab
beside the one that closed and is deleted only when nothing is left for it to
show. With `ecc-tab-line-mode` off nothing changes.

### Packaging and documentation

Every source file now opens with the GPL-3.0-or-later notice that `LICENSE` and
the README already named, an SPDX line, a `Maintainer` and a `URL`.
`Package-Requires` is written in `ecc.el` alone, where an installer reads it,
rather than copied into forty-two files that were each a chance to name a
different Emacs. `make lint` runs the package checker instead of skipping it
and fails on its errors, and CI installs the checker so that the job means
something.

The comparison table in the README said two of the four other projects are
published in a package archive. Neither is, and the table also listed `eca`
among the dependencies of `eca-emacs`, which is that package itself. Every
project's `Package-Requires` was read again while correcting it.

`CHANGELOG.md` has the full record.
