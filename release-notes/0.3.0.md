Verified against **Claude Code CLI 2.1.274** and Emacs 30.1.

### A Space for every project

The windows are laid out a new way, and it is what a fresh install now does. Every project gets a tab of the tab bar -- a Space -- and the windows inside it are yours. Transcripts stand side by side and are never stacked; a tab is a window arrangement, so going to another Space and back brings the whole of it back the way you left it. A worktree is a Space of its own, drawn under the repository it came from.

`C-c c j` goes to a Space, `C-c c z` fills the tab with one window and puts it back, and `C-c c V` deals the arrangement out again -- the source of the project on the left, the transcripts beside it.

`(setq ecc-use-spaces nil)` is the way back to what this package has always done: side windows with roles, no tabs, no sidebar and no worktree commands.

### A sidebar

`C-c c b` opens a narrow window down the left of the frame: the Spaces at the top -- every project and worktree, numbered, each marked with what it is doing and what branch it is on -- and the sessions at the bottom, with what each is waiting for. It stays on the screen while you work, which is the one thing the dashboard does not do, and it never takes the selected window.

`RET` goes to what a row stands for, `1`-`9` go to a Space by its number, `TAB` folds a repository's worktrees away, `a` and `d` answer a session, `k` stops one, `W` makes a worktree and `X` removes one. The dashboard is `C-c c B` now -- the same list, in the form that does not stay on the screen.

### Worktrees

A session can live in a worktree of its own. `W c` in the menu checks a branch out beside the repository and starts a session there, `W o` starts one in a checkout that exists, and `W k` stops the sessions working in a checkout and undoes it. Stopping the last session in a worktree offers to remove it there and then, wherever the session went. The branch always outlives the checkout: removing a worktree can lose nothing that was committed.

With the Emacs MCP server on, the model is offered `start_worktree_session`: asked for something to be done on a branch of its own, it names the branch and writes the brief, and Emacs makes the checkout, opens it as a Space, starts a session there and sends it that brief -- with the files the conversation touched, the plans it wrote and the changes that are still uncommitted added to it. Left to itself the CLI would run `git worktree add` and carry on in the same session, which leaves one conversation working in two checkouts; `EnterWorktree` and `git worktree add` are refused with a sentence naming the tool instead.

### `/resume` in a session

Typed in a session, `/resume` carries that window on with another recorded conversation of the project. The window, the tab, the buffer, the session name and the review baseline do not move -- what changes is which conversation is in them, which is what the terminal client's own `/resume` does.

### Images and video in the transcript

Pictures are drawn where they arrive: an image block on a message, an image inside a tool result, a file a tool named, and the images a prompt attached as `@path`. None of it reaches the buffer as base64. A GIF moves by itself and stops itself, `v` stops the picture at point or sets it going again, and `RET` opens one. Where `ffmpeg` is on `PATH`, a video shows its first frame. `ecc-image-inline` turns the drawing off.

### Reviewing

- `ecc-review-style` set to `'ediff` opens `D` and `G` in ediff instead of one `diff-mode` buffer: every file of the review in one session, so `n` and `p` walk every difference across the file boundaries, both sides read-only, and `?` shows a help written for the review rather than ediff's own.
- `C-c C-c` in a review sends the comments instead of opening a buffer to confirm them in. `C-u C-c C-c` opens that buffer for the times there is something to say about the change as a whole.

### The prompt

- `C-c C-r` picks a past prompt from a list and inserts it at point, where `M-p` walks the history one entry at a time.
- The footer names the model before the session has answered, worked out from the session, the environment and the Claude Code settings files, rather than waiting for the first assistant message to say it.

### Breaking

- **The Spaces have the lower-case keys.** `C-c c j` goes to a Space rather than focusing a project, `C-c c b` opens the sidebar and `C-c c B` the dashboard -- the two swapped. `C-c c V` puts the tab in order, `C-c c C` no longer makes a worktree (it is `W c`), and `w` in `ecc-menu` rewrites the region where `W` is the worktree menu.
- **`ecc-toggle` and `ecc-toggle-all` are gone**, with `C-c c w`. What puts a session back on the screen is `C-c c V`, or going to the session.
- **`ecc-window-focus-source` is no longer a command**, `ecc-space-reset-windows` having taken its key and its job.
- **`ecc-prompt-resend-last` is gone**, with its `C-c C-r`. `M-p C-c C-c` is the two keys that did what it did.
- **`ecc-review` reviews everything that changed since the session started**, rather than the files the CLI reported editing or writing -- a file changed by a shell command or a script is in the review now, and that is most of what a session does. `ecc-review-untracked-max-bytes` is `ecc-review-max-bytes`, with the old name kept as an obsolete alias.
- The layout setting is `ecc-use-spaces`, a boolean defaulting to `t`. `ecc-hooks-settings-files`, `ecc-hooks-user-directory` and `ecc-hooks-managed-files` moved to `ecc-protocol-` names; nothing a user sets changes name.

This release includes eleven fixes as well, among them a session that followed the CLI's cwd out of its own project, a notice the CLI injected drawn as a prompt somebody typed, and `make compile` compiling each file in an Emacs of its own -- which caught three files that would not compile on their own. `CHANGELOG.md` has the full record.
