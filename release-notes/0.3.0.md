Verified against **Claude Code CLI 2.1.274** and Emacs 30.1.

### A Space for every project

Window layouts have been redesigned, and the new layout is enabled by default on fresh installs. Every project gets a tab on the tab bar -- a Space -- and the windows inside it are yours to arrange. Transcripts appear side by side and are never stacked. Because a tab preserves its window arrangement, switching to another Space and back restores the layout exactly as you left it. Each worktree is its own Space, displayed under the repository it came from.

`C-c c j` switches to a Space, `C-c c z` expands one window to fill the tab and restores it, and `C-c c V` resets the layout -- the project source on the left, transcripts beside it.

Set `(setq ecc-use-spaces nil)` to restore the previous behavior: side windows with roles, no tabs, no sidebar, and no worktree commands.

### A sidebar

`C-c c b` opens a narrow window on the left of the frame. Spaces appear at the top: every project and worktree is numbered and shows its current activity and branch. Sessions appear at the bottom, showing what each is waiting for. Unlike the dashboard, the sidebar stays on screen while you work, and it never takes the selected window.

`RET` opens the item on the current row, `1`-`9` jump to a Space by number, `TAB` folds a repository's worktrees away, `a` and `d` answer a session, `k` stops one, `W` creates a worktree, and `X` removes one. The dashboard is now `C-c c B` -- the same list, in a window that does not stay on screen.

### Worktrees

A session can run in its own worktree. In the menu, `W c` checks out a branch beside the repository and starts a session there, `W o` starts one in an existing checkout, and `W k` stops the sessions running in a checkout and removes it. Stopping the last session in a worktree offers to remove the checkout immediately, wherever the session was closed. The branch always outlives the checkout: removing a worktree cannot lose anything that was committed.

With the Emacs MCP server enabled, the model is offered `start_worktree_session`. When asked to do work on a separate branch, the model names the branch and writes a brief. Emacs then creates the checkout, opens it as a Space, starts a session there, and sends it that brief, along with the files touched by the conversation, the plans it wrote, and any uncommitted changes. Left to itself, the CLI would run `git worktree add` and continue in the same session, leaving one conversation working across two checkouts. Instead, `EnterWorktree` and `git worktree add` are rejected with a message naming the tool.

### `/resume` in a session

When typed in a session, `/resume` continues that window with another recorded conversation from the project. The window, tab, buffer, session name, and review baseline stay in place; only the conversation inside them changes, matching how `/resume` works in the terminal client.

### Images and video in the transcript

Images are displayed inline where they arrive: an image block on a message, an image inside a tool result, a file named by a tool, and images attached to a prompt with `@path`. None of it reaches the buffer as base64. Animated GIFs play and stop automatically. `v` pauses or restarts the image at point, and `RET` opens it. When `ffmpeg` is on `PATH`, a video displays its first frame. `ecc-image-inline` turns off inline images.

### Reviewing

- Setting `ecc-review-style` to `'ediff` opens `D` and `G` in ediff instead of a single `diff-mode` buffer. Every file in the review is included in one session, so `n` and `p` step through differences across file boundaries. Both sides are read-only, and `?` shows help written for the review rather than ediff's own.
- `C-c C-c` in a review sends comments immediately instead of opening a buffer to confirm them. `C-u C-c C-c` opens that confirmation buffer when you want to comment on the change as a whole.

### The prompt

- `C-c C-r` selects a past prompt from a list and inserts it at point, while `M-p` steps through history one entry at a time.
- The footer shows the model name before the session responds, determining it from the session, the environment, and Claude Code settings files instead of waiting for the first assistant message.

### Breaking

- **The Spaces have the lower-case keys.** `C-c c j` switches to a Space instead of focusing a project. `C-c c b` opens the sidebar and `C-c c B` opens the dashboard -- the two keys have swapped. `C-c c V` resets the tab layout. `C-c c C` no longer creates a worktree (it is now `W c`), and `w` in `ecc-menu` rewrites the region while `W` opens the worktree menu.
- **`ecc-toggle` and `ecc-toggle-all` are gone**, along with `C-c c w`. To restore a session to the screen, use `C-c c V` or switch to the session.
- **`ecc-window-focus-source` is no longer a command**; `ecc-space-reset-windows` has taken over its key and its job.
- **`ecc-prompt-resend-last` is gone**, along with its `C-c C-r`. Pressing `M-p C-c C-c` does what it did.
- **`ecc-review` reviews everything that changed since the session started**, instead of only the files the CLI reported editing or writing. Files changed by shell commands or scripts are now included in the review, which is most of what a session does. `ecc-review-untracked-max-bytes` is now `ecc-review-max-bytes`, with the old name kept as an obsolete alias.
- The layout setting is `ecc-use-spaces`, a boolean defaulting to `t`. `ecc-hooks-settings-files`, `ecc-hooks-user-directory`, and `ecc-hooks-managed-files` moved to `ecc-protocol-` names; no settings that users configure have changed names.

This release also includes eleven fixes. Among them are a session that followed the CLI's cwd out of its own project, a notice injected by the CLI displayed as a user-typed prompt, and `make compile` compiling each file in its own Emacs process -- which caught three files that would not compile on their own. `CHANGELOG.md` has the full record.
