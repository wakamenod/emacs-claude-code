Verified against **Claude Code CLI 2.1.290** and Emacs 30.1.

A second release about how ecc is put together. No command, key or setting
changes, and a session looks and behaves as it did in 0.4.4.

### The lower modules no longer load the ones above them

0.4.4 had `ecc-chat-mode` load six modules above it, so that every chat
buffer had their keys. Now the function that makes a session buffer loads the
whole package first, the way starting a session already did. The keys, the
prompt's completion and the hint in the mode line are there however the buffer
came.

`ecc-window` no longer calls into `ecc-space`. What depends on the layout is a
generic function in `ecc-window` with the `classic` answer as its default, and
`ecc-space` adds the `spaces` answer.

Calls from a module into one that requires it went from 67 to 44, and forward
declarations from 97 to 90.

### What you might notice

- A recording opened with `ecc-history-open` or `ecc-search` in an Emacs that
  had loaded nothing of ecc now loads the whole package, as starting a session
  does.
- Three docstrings that wrote out a key of ecc's own now show the key the
  command is bound to, so they follow a rebinding. The `ecc-resume` docstring
  shows the key you bound, or `M-x ecc-resume`.
- `C-h f ecc-global-map` now finds where it is defined.

`CHANGELOG.md` has the full record.
